# 拾绪 ShiXu · 产品规格 v1

状态：开发指南基线，尚未实现产品。用于黑客松的 AI 情绪陪伴养成 Web 应用。用户记录触动自己的日常，陪伴一个最初全白、无表情、无装饰的全身小人成长。核心是情绪共生与陪伴，不评价用户情绪的好坏，不要求用户保持快乐。

## 1. 最小体验闭环

1. 进入页面，看到初始小人或恢复的本地角色。
2. 输入原文日记，不设产品人为字数上限；仅用 `text.trim().length > 0` 判断非空白，保存的仍是未经 trim 的 text，完整保留空格、换行、标点和内容。选择 Jev 识别或直接手动选择。
3. 查看情绪类别与维度；接受或纠正，明确点击保存。识别期间不改变存档。
4. 规则引擎计算表情、动作、临时装饰可见性、成长和回忆，保存为一次整体更新。
5. 页面展示变化及简短原因；刷新后仍保留记录和成果。允许在回忆中恢复隐藏装饰。

提交按钮防重复；同一 entryId 只能创建一条正式记录。取消识别、关闭草稿不产生奖励。手动路径和 AI 路径使用相同规则，没有 AI 的用户也能完整体验。

默认界面语言为简体中文。用户输入本身就是日记，不做 AI 润色、总结、扩写、改写或生成。每条日记保存 id、createdAt、固定 dayKey、revision、必要的更新时间/修订状态及一个最终确认的 effectiveEmotion，字段见架构。历史列表支持查看完整正文；保留日记编辑功能，P5 完善浏览与编辑体验。正文编辑原样替换 text，保留创建信息、所有奖励与原有心情，不触发经验、解锁或隐藏/恢复；重新识别须用户主动发起并再次确认，主动手动纠正同样可用。

日记存储与 AI 输入限制分离：模型无法处理全文时明确提示，保留完整草稿并允许手选保存；不静默截断或伪装成全文分析。Jev 失败、超时、未配置 Key 时同样可手选。localStorage 容量/权限属于实际存储限制，保存失败必须保留草稿及旧存档并提示未保存；只有写入成功才显示持久保存成功，刷新后恢复日记、心情和角色。异常恢复见架构。

## 2. 情绪共生

情绪类别与维度见 [AI_CONTRACT](AI_CONTRACT.md)。V、A、D 均为 0–1：V 表示愉快程度，A 表示激动程度，D 表示主观控制感，不是情绪好坏评分。规则以确认后的数值为依据，不从类别名称再次推算一套数值。

以下数值是便于实现的 MVP 原型参数，不声称经过心理学验证；后续调整统一修改本规格及对应 rulesVersion，不分别散落在组件里。

| 输入条件（按表顺序匹配） | 表情 / 规则选定动作 | 视觉表现 |
| --- | --- | --- |
| 无正式记录 | 无表情 / idle | 纯白、无配件 |
| V <= 0.35 且 A >= 0.65 | 担忧 / soothe | 轻微缓动；D < 0.35 时增加小幅蜷缩姿态 |
| V <= 0.35 且 A < 0.65 | 悲伤 / settle | 垂眼、淡色泪滴或小雨效果 |
| V >= 0.65 且 A >= 0.65 | 开心 / celebrate | 微笑、短暂跳动和星光 |
| V >= 0.65 且 A < 0.65 | 安心 / breathe | 轻微呼吸与柔和光点 |
| 其他 | 平静 / idle | 温和中性表情 |

intensity 控制特效透明度与幅度（有限范围，不无限放大），不影响永久扣减。效果在正常模式下轻柔；减少动态效果模式静态显示同一情绪。瞬时动作结束回到当前情绪对应的静态姿态/idle，不触发模型调用或发奖。全身白色基底不随 V 改成其他肤色。

## 3. 成长与奖励

- 每条首次确认保存的新记录给予 5 点表达经验；V >= 0.65 时额外 5 点。消极记录同样值得被接纳。
- 每个 dayKey 经验上限 20，超出仍可记录、改变情绪和产生回忆，仅不增加经验。dayKey 在首次确认提交时按浏览器当日本地日历生成 YYYY-MM-DD 并冻结，同一次操作保存失败后重试复用原值，跨午夜不重新归日；新建另一条记录才使用新的当日 dayKey。
- 永久经验只增不减；成长阶段按阈值 0「初遇」、30「相伴」、80「共生」计算，不回退。阶段先只体现细微比例/姿态变化，不扩展为复杂物种进化。
- 首次达到经验 10 解锁 ribbon、30 解锁 scarf、80 解锁 star-pin；物品的 stable id、槽位、是否 celebration 标签由规则目录维护。示例对应 head、body、badge，均可标为 celebration。
- 解锁代表拥有；首次可自动装到空槽位，不强制替换用户已有选择。已解锁物品不重复发放。
- 所有分支共用一份规则配置，版本初始为 rules-v1。后续调参不追溯扣除经验、阶段或物品。

## 4. 装饰隐藏与恢复

| 事件 | 行为 | 必须保留 |
| --- | --- | --- |
| 新记录 V <= 0.35 且 intensity >= 0.6 | 从当前已装备、可见且带 celebration 标签的装饰中按 stable id 升序最多隐藏 1 件 | 所有权、原槽位、隐藏原因、sourceEntryId、隐藏时间 |
| 无符合条件的装饰 | 只显示悲伤效果 | 全部已有成果 |
| 新记录 V >= 0.65 | 恢复全部因情绪隐藏的装饰 | 每件原有记录与恢复事件 |
| 用户点击恢复 | 无条件恢复所选已拥有装饰 | 不要求积极情绪或额外付费/经验 |
| 刷新、后台计时、离线返回 | 不再次隐藏、不补算损失 | 当前存档 |

恢复仅清除隐藏标记，不抢占用户已更换的装备槽位；原槽位被占时回到可装备物品列表。隐藏与恢复分别产生回忆事件。恢复后不会因当前仍悲伤而立刻再次隐藏，只有下一条符合条件的新记录才可触发。

隐藏保留 equippedBySlot 的原有选择；用户更换或卸下后，hiddenById 仍保留来源槽位和回忆。已拥有且未隐藏的物品才可穿戴，穿戴到目录定义的槽位，同槽新物品替换旧物品，旧物品仍归用户；卸下只清除该物品的槽位引用。隐藏物品先显式恢复再穿戴。恢复时若该物品仍在原槽位则直接可见；若已被换下或卸下，仅清除隐藏标记，保留空槽或现有装备，用户可再次主动穿戴。穿戴/卸下不发经验或解锁，不删除隐藏/恢复历史，不引入商城或额外养成系统。

## 5. 纠正与回忆

- 保存前纠正：采用用户选择的类别和维度，只保存一次有效结果；保留经 Provider 校验并转换的原始 AI 建议用于本地查看，不保存厂商原始响应，不作为状态操作。
- 保存后纠正：记录原建议、原有效结果、新有效结果和修订号；不重复发经验、不追回已发奖励、不删除历史。用户文本不在纠正时被改写。
- 经验、解锁及新隐藏/全量恢复只在首次 CONFIRM_ENTRY 时结算一次；纠正不重新结算，也不回放历史。纠正最新记录可更新当前情绪和视觉；若新结果不再满足隐藏条件，仅清除仍由该 entryId 造成的有效隐藏标记，并记一次恢复回忆。仍满足条件则保留现有标记，不换目标、不新增隐藏；以后再次纠正为消极也不重新隐藏。纠正不恢复其他记录的隐藏，不撤销已经发生的恢复、穿戴、解锁或奖励。
- 用户主动恢复后，原隐藏标记已清除，同条记录任何修订都不能再创建它；只有另一条首次确认的新记录才有新的隐藏资格。纠正旧记录仅更新该记录与纠正回忆，不覆盖最新记录的当前情绪，也不改变装饰。
- eventId 标识一次操作，重试复用；entryId 标识一条日记，首次保存只结算一次。正文编辑和情绪纠正共用递增 Entry.revision 与旧修订校验，新修订不获得新的奖励/隐藏资格；领域事件及隐藏事件关联见架构。
- 回忆经 entryId 关联日记，保存时间、事件类型、确认后的情绪、识别来源、修订记录和规则产生的成长/解锁/隐藏/恢复摘要；Entry 是正文唯一正式存储位置，回忆事件不重复复制完整正文，普通回忆详情展示该 Entry 编辑后的最新正文。情绪纠正历史与成长事件完整保留，普通负面情绪不会删除任何历史。
- MVP 先用简单列表和装饰回忆卡；之后增加按日期的时间线、阶段里程碑、纪念品。纪念品由确定性规则按已确认事件生成，AI 不直接发放。

## 6. 长期陪伴与范围

后续自主行为只由规则根据当前情绪、显式时间输入和事件选择 idle/breathe/peek 等有限动作；不加入饥饿惩罚、连续登录压力、离线衰减或强制打卡。角色欢迎用户回来，不指责离开。

MVP 不做无限聊天、语音、3D、社交交易、多人、商城付费或医学诊断。文本只在用户点击 AI 识别时发送到服务端模型；手动路径不发送。浏览器数据不自动跨设备同步，清除站点数据会丢失本地存档；导出/导入放在体验完善阶段。用户主动删除/重置是独立明确操作，不能作为情绪后果。

## 7. 一次验收的可见结果

人工用一条积极、一条消极和一次恢复走完：有表情变化，经验不回退，隐藏物品可找回，刷新后数据仍在；再用手动选择完成一次无 API 路径。纠正不重复发奖，已有有效验收无需重复执行。
