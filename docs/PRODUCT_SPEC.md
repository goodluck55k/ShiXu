# 拾绪 ShiXu · 产品规格 v4

> 状态：V1 方向基线。本文描述**产品要做什么**，不规定实现细节；数值参数集中在 [COMPANION_SPEC](COMPANION_SPEC.md) §2–§5，接口与存档结构见 [ARCHITECTURE](ARCHITECTURE.md)。标注「已实现」的内容以 `main` 分支代码为准，标注「候选」「待确认」的内容不得当作已批准规则。
>
> 文档版本为 v4；存档 `schemaVersion` 仍为 3。文档升版不等于存档升版。

## 1. 产品定位与当前状态

拾绪是一个情绪陪伴养成 Web 应用：用户写下真实的日记、确认自己的心情，一个原本全白、没有装饰的小人按确定性规则慢慢形成性格，并用表情、动作、主导行为、离线生活和久别重逢把这种长期变化表现出来。

V1 的四件事：

1. **情绪记录**：原文日记 + 九类情绪手动确认 + 可选 AI 建议。
2. **长期性格养成**：性格由长期确认过的情绪逐渐形成，不是当前心情的复制，也不是一次性数值奖励；五维独立累计，只表现当前最高分的主导性格。
3. **自主行为与互动**：主导性格决定小白人偏爱做什么、怎么回应；当前情绪只影响即时表情与反馈；用户能感到「这是我的小人，它和我相处久了」。
4. **离线生活与久别重逢**：用户离开后，小白人按自己的性格过有限的生活；长期未访问后再次打开，它会主动问候，但不惩罚、不加分、不制造负罪感。

设计取向：长期陪伴、个体差异、养成感。不追求短期刺激、连续签到、等级战力或收集压力。

## 2. 核心循环

1. **写日记**：用户写下当天的正文。正文原样保存，不做 AI 改写、润色或生成，不设产品人为字数上限。
2. **确认心情**：用户从九类情绪中选择一类，并可调整 VAD 维度与强度；AI 建议只是可选辅助，必须由用户确认或修改后才进入保存。
3. **保存并成长**：保存成功后，性格引擎按确定性规则把这次「已确认情绪」计入五维贡献账本，并重新判定主导性格；保存失败不产生任何正式成长。
4. **陪伴与行为**：小白人依据主导性格、当前情绪、显式互动和时间/种子上下文做出自主行为与即时反馈；当前情绪只改变表情和幅度。
5. **离开与回来**：用户离开后，小白人按主导性格生成有限的离线生活事件；长期未访问后再次打开，触发一次久别重逢问候，随后回到日常陪伴。
6. **回看**：用户在回忆页查看历史日记与情绪，在陪伴页观察主导性格描述、行为差异与离线生活。

一次记录只发生一次成长结算；重复点击、刷新、重试不会重复计分；纠正情绪替换原贡献而不是叠加；编辑正文不改变性格贡献；离线生活和重逢回答不产生性格贡献。

### 2.1 六种机制

| 机制 | 职责 | 不负责 |
| --- | --- | --- |
| 情绪确认 | 规范化九类情绪与 VAD；给出手选与 AI 建议两条路径 | 不直接改性格、不决定动作 |
| 性格养成 | 把长期确认情绪累积成五维倾向；维护贡献账本、规则版本与主导性格 | 不渲染界面、不直接选择动作、不展示分数 |
| 主导行为 | 依据当前主导性格、互动与上下文选择有限行为 | 不改性格、不写存档、不调用 AI |
| 互动反馈 | 对呼唤/触碰/观察等显式互动给出即时反应；保存后给一次性情绪反馈 | 不刷性格、不产生持久奖励 |
| 离线生活 | 按离线时间与主导性格生成有限生活事件 | 不改分数、不伪造日记、不惩罚、不掉资源 |
| 久别重逢 | 判断长期未访问、生成一次问候并记录触发窗口 | 不把回答当日记、不改分数、不实时调用大模型 |

## 3. 情绪

- 九类情绪正式枚举固定为：`joy`、`calm`、`sadness`、`anxiety`、`anger`、`tired`、`mixed`、`neutral`、`unknown`。本文使用讨论用名「喜悦、平静、悲伤、焦虑、愤怒、疲惫、复杂、中性、未知」；当前界面显示名可能不同（例如 `joy` 显示「开心」、`neutral` 显示「平常」），差异清单见 [COMPANION_SPEC](COMPANION_SPEC.md) 2.4，不得为统一文案而改写枚举。
- 每条情绪记录包含 `valence`、`arousal`、`dominance`、`intensity`（0–1）、`confidence`（AI 为 0–1，手动/纠正为 `null`）与来源 `source`（`ai` / `manual` / `corrected`）。
- 手选情绪使用 [AI_CONTRACT](AI_CONTRACT.md) §4 的默认 VAD；用户可在保存前调整维度与强度。
- AI 识别是可选项：未配置 API Key 时必须能只用手选完成完整主流程；AI 失败、超时、格式错误、低置信度都必须回落到手选，且用户始终可以改判。
- 情绪标签是五维性格结算的主依据；VAD 与强度用于即时表情、动作幅度和强度系数，不额外制造第二套评分。置信度只用于提示用户复核，不参与计分。
- 用户纠正已保存记录的情绪时，只替换该条贡献并重算该条；其当前描述可随替换变化，但不得以追加惩罚、批量回滚或追溯其他日期的方式删除、回退已形成结果。迁移前没有新贡献的旧条目，纠正只更新情绪与历史，不补算分数。

## 4. 性格养成

性格是小白人的**隐藏行为倾向**，不是用户的健康指标、心理诊断或人格测评，也不直接展示精确分数。

- 五维（已确认）：温柔 `gentleness`、好奇 `curiosity`、开朗 `cheerfulness`、害怕 `fearfulness`、低落 `low_mood`。
- 「害怕」和「低落」是有效性格倾向，不是错误状态或惩罚机制。「低落」只代表游戏中的长期低落倾向，不是抑郁症诊断；不得根据评分推断用户的心理疾病。
- 五维独立累计，不做归一化，不强制总和固定；初始状态为中性基线。具体初始分、上下限、单次/单日上限、强度与惯性系数见 [COMPANION_SPEC](COMPANION_SPEC.md) §2.5，均为候选或待确认参数。
- 每类情绪对五个维度有方向不同的基础影响；强度参与幅度缩放；VAD 不重复计分，主要用于当下表现。候选评分表不是最终数值验收，见 [COMPANION_SPEC](COMPANION_SPEC.md) §2.3。
- 性格可以**双向缓慢变化**：长期偏向某一侧后，设计上允许继续同方向变化因惯性而减小；但惯性公式尚未确认，未确认前取 `roomFactor = 1.0`，不得把“惯性必然生效”写成已实现事实。单次记录不能造成剧变。
- 悲伤、焦虑、愤怒**不是人格缺陷**，也不触发任何惩罚、扣减资产或负面标签；不得把负面情绪写成“需要被修正”的失败。
- **只表现最高分主导性格**：五维分数仍独立保存和更新，但小白人的主要行为风格只由当前最高分维度决定；其他维度不直接参与主要行为选择。其他维度严格超过当前主导后，允许主导切换。
- 并列时需要稳定、确定性的选择规则，避免反复切换；具体规则见 [COMPANION_SPEC](COMPANION_SPEC.md) §2.7。
- 即时情绪可以短暂影响表情，但不能覆盖主导性格的长期行为规则。
- 用户只能看到当前主导性格的自然语言描述与行为差异，不能查看五维分数、排名、进度、雷达图，也不能手动加点或选择培养路线。
- 规则以版本标识（候选 `personality-v2`）固定在配置中；调整规则不追溯改写已保存记录；旧贡献按自己的规则版本解释。
- 「性格状态查询」是只读契约：行为、角色展示、离线生活、久别重逢和未来的 V2 饰品模块都只能读取，不能写性格内部状态。

## 5. 自主行为、离线生活与久别重逢

### 5.1 主导行为与互动

- 行为由**确定性规则 + 有限行为集合**产生，不使用复杂行为树、通用游戏引擎或多模型编排。
- 行为上下文 = 只读主导性格快照 + 当前已确认情绪 + 显式互动事件 + 应用层显式提供的时间/种子。
- 行为分为四类并逻辑分离：普通待机、主导性格行为、连续低落特殊行为、用户主动互动。
- **主导性格决定主要行为池**：温柔、好奇、开朗、害怕、低落各有独立的行为候选；其他维度分数不参与主行为加权。
- 当前情绪只决定即时表情、眼神、动作幅度和速度，不改变主导行为池，也不把“当前悲伤”直接变成长期低落。
- 互动可以短暂打断主导行为，结束后回到主导池；互动不得直接增加性格分数或绕过保存流程。
- 同一时刻只有一个主要行为；每种行为保留最低出现机会；同一行为不连续超过两次（候选参数）。
- 页面隐藏时暂停行为调度与动画；关闭网页不运行后台 Agent，也不在关闭期间持续推进生活。
- 行为模块可以新增动作而不修改性格算法；角色展示层只负责按 `CharacterView` 渲染，不修改性格或存档。
- AI 不得决定动作、生成可执行行为指令，也不参与行为选择。

连续低落特殊行为：

- 只有同时满足两个条件才允许触发：`low_mood` 是当前最高分主导性格；用户连续超过 3 个自然日记录低落情绪（第 4 天开始符合条件）。
- 符合条件后按配置概率出现喝酒、抽烟等虚构角色的颓废行为；不是必然触发。
- 不产生奖励、成长加成或额外性格积分；不把喝酒、抽烟表达为改善情绪的方法。
- 主导性格不再是低落、连续低落中断时停止触发；没有记录的自然日不得自动算作低落日（是否中断连续属于待确认判定，见候选规则，不在此写成已确认）。
- 「低落情绪」对应哪些正式情绪标签尚未确认；候选仅 `sadness`。确认前特殊行为默认关闭，详见 [COMPANION_SPEC](COMPANION_SPEC.md) §3.5。
- 该机制只作用于虚构角色，不用于判断用户的心理健康状况。

### 5.2 离线自主生活

- 用户离开后，小白人仍然拥有自己的生活；再次打开时，按上次访问时间与当前主导性格生成有限离线事件。
- 离线活动按主导性格区分：温柔整理房间/照顾植物/安静休息；好奇探索房间/观察新事物/收集发现；开朗玩耍/跳舞/尝试游戏；害怕待在熟悉角落/小心探索；低落发呆/睡觉/靠窗沉思。
- 离线生活**不改变五维分数**；用户长时间不登录，不会因此增加低落，也不会减少任何维度。
- 不因离线惩罚用户：不掉资源、不掉饰品、不掉装扮、不掉已形成的成长；V1 饰品系统本来就不实现。
- V1 不要求后台持续运行 Agent；使用上次访问时间和确定性事件生成机制，只生成有限数量的离线事件。
- 事件需要持久化和幂等：同一离线时间段不得重复生成；保存失败时不得出现半写状态。
- 离线生活模块与性格评分模块独立；离线模块只读主导性格，不读贡献账本、不写分数。
- 不通过伪造情绪日记来“解释”离线生活；离线事件不是日记，不进入回忆。

### 5.3 久别重逢

- 建议将超过 3 天未访问作为 V1 的长期离线阈值（候选，可配置）。
- 用户重新打开 ShiXu 时，小白人主动询问：「最近过得还好吗？」
- 根据当前主导性格，可以使用不同的问候语气和生活经历描述；模板可配置，不要求实时调用大模型。
- 同一次重逢只触发一次；页面刷新不得重复触发。
- 用户可以回答，也可以跳过；回答默认不改变性格评分，只有正式保存的情绪日记才会产生性格贡献。
- 不使用责备、道德绑架或制造负罪感的文案；问候不是情绪日记，不写入 `entries`。
- 保存失败时不展示问候，避免“显示了但没记住”导致刷新重复。

## 6. 页面责任

V1 保留三个路由，页面职责如下：

| 路由 | 页面 | 责任 |
| --- | --- | --- |
| `/` | 记录 | 写日记、选择或调整情绪、查看 AI 建议并确认、保存；处理保存失败、草稿、异常恢复提示 |
| `/companion` | 陪伴 | 展示小白人、当前表情/动作、主导行为、互动入口、**当前主导性格**的自然语言描述；展示离线生活事件与重逢问候（保存成功后）；保存成功后的一次性情绪反馈 |
| `/memories` | 回忆 | 按时间查看历史日记原文与当时确认的情绪；支持纠正情绪、编辑正文；展示必要的保存状态 |

页面只通过应用服务与公开契约读写状态，不直接访问其他模块的私有数据。陪伴页不得展示五维分数、排名或进度；不得把非主导维度的描述列成“性格面板”。

## 7. 数据与存档

- 正式状态以完整 `Snapshot` 为单位一次写入；只有存档成功后才确认成长结算、离线事件与重逢触发。
- 存档带版本号、修订号与幂等事件记录；旧版本存档在读取时迁移，迁移不修改已有日记正文、情绪、纠正记录与历史。
- v2→v3 迁移把旧 `character.totalXp/stage`、三维 `companion` 台账与 `decorations` 移入 `legacy`；新五维从初始值开始，不追溯旧日记，不自动换算三维。
- 离线生活与重逢状态随快照持久化；`SESSION_STARTED` 事件保证同一离线窗口只处理一次。
- 损坏、不可识别或版本过新的存档保留原始数据，提供导出/重置路径，不静默覆盖。
- 不要求登录、云同步、数据库或后端账号体系；V1 使用浏览器本地存储，通过 `StoragePort` 隔离。
- 详细结构、迁移规则与失败处理见 [ARCHITECTURE](ARCHITECTURE.md) §4、§6。

## 8. 范围与非目标

V1 明确不做：

- 饰品、装扮、库存、解锁/隐藏/恢复/穿戴玩法与对应界面。
- 商城、交易、点数、货币或付费内容。
- 经验值、等级、成长阶段、每日签到、连续天数奖励等旧成长体系。
- 复杂 Agent、多模型编排、微服务、消息队列、向量库或通用插件系统。
- 社交、PK、多人、语音、3D、无限聊天或医学/心理诊断。
- 后台持续运行的离线 Agent、离线成长加速、离线衰减或长期不登录惩罚。
- V1 稳定前提前实现 V2 业务。

旧机制处理：

| 旧机制 | 处理 |
| --- | --- |
| 每篇日记 XP、阶段（0/30/80）、XP 解锁饰品、消极情绪隐藏饰品 | 废止，不再结算、不再展示；旧存档字段只做兼容保留 |
| 装饰三态、动态回收、穿戴槽位 | 后置到 V2；V1 不实现、不评估、不展示 |
| 长期习惯、世界成长痕迹、情绪种子 | 不属于 V1；旧存档数据保留但不参与 V1 规则 |
| 三内部维度（探索欲/静心度/亲近倾向） | 由新五维性格体系替代；旧台账移入 `legacy`，不追溯换算（待确认） |
| 旧五维草案（活泼/勇敢/温柔/敏感/好奇） | 从未在 `main` 实现，不作为迁移来源；新五维见 §4 |

## 9. V2 饰品扩展边界

V1 只为 V2 预留**契约级**扩展点，不实现任何饰品业务：

1. **只读性格查询**：V2 可按性格快照与成长事件判断装扮表现，但不能写性格内部状态。
2. **已确认领域事件读取/消费**：V2 可消费 `ENTRY_SAVED`、`EMOTION_CORRECTED` 等已落盘事件，自行维护饰品状态。
3. **角色外观扩展点**：`CharacterView` 预留可选外观配置（图层白名单），V2 通过注册外观提供者叠加饰品图层；角色展示层仍只渲染，不判定解锁。

V1 不实现饰品库存、装扮 UI、解锁算法、动态插件加载器或复杂事件总线；现有通用接口能满足时不新增重复接口。V2 必须作为独立模块和独立阶段接入，不大规模重构性格与行为核心。

## 10. 演示与验收

最小可演示线：

1. 新用户写一篇日记，手动选择心情并保存；刷新后正文、情绪与主导性格描述仍在。
2. 同一天重复点击保存不重复计分；编辑正文不改变性格；纠正情绪后描述按替换规则变化。
3. 连续多天记录不同情绪后，五维分数在内部变化，但界面只表现最高分主导性格的行为与描述；主导切换符合严格超过/并列保留规则。
4. 陪伴页的小白人按主导性格做出对应行为；当前情绪只改变表情/幅度；互动有即时反应，且不增加性格分数。
5. 关闭页面再打开：同一离线窗口的离线事件只生成一次；长时间离线不增加 `low_mood`，不掉资源。
6. 超过 3 天未访问后再次打开：只触发一次「最近过得还好吗？」；刷新不重复；回答或跳过不改变性格分数。
7. 未配置 AI Key 时手选全流程可用；配置 Key 后 AI 建议必须经用户确认才生效；AI 不参与主导判定、行为、离线或重逢。
8. 损坏存档、版本不兼容、存储不可用时有明确提示与恢复路径。

详细数值验收与阶段验收见 [ROADMAP](ROADMAP.md) 与 [COMPANION_SPEC](COMPANION_SPEC.md)。
