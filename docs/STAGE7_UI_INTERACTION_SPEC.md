# 拾绪 ShiXu｜阶段七正式 UI 与交互交接规格 V1

> 编制：2026-11-13。性质：**用户已确认的设计决策 + 明确标注的实施建议**，不是阶段七已完成的代码或最终美术资源。本文是阶段七设计基线，不代表实现完成。
>
> 适用项目：https://github.com/goodluck55k/ShiXu
> 上位约束：`AGENTS.md`、`docs/PRODUCT_SPEC.md`、`docs/COMPANION_SPEC.md`、`docs/ARCHITECTURE.md`、`docs/AI_CONTRACT.md`；本稿落实 `docs/STAGE7_DESIGN.md` 的 UI/视觉部分。

## 1. 已确认：产品视觉与页面结构

- 用户进入网站时默认看到 **企鹅小屋**（`/`）；日记与企鹅在不同页面，**不做同屏分栏**。
- 三个独立入口：**企鹅小屋 / 心情日记 / 回忆碎片**。已确认 URL 分别为 `/`、`/diary`、`/memories`；建议既有 `/companion` 保留兼容路径或重定向。当前仓库实际仍是 `/` 日记、`/companion` 陪伴、`/memories` 回忆，迁移尚未执行。
- 企鹅小屋为 **绘本式生活空间**；总体克制留白且有少量生活故事感。场景光线仅轻微变化，不做显著昼夜切换。
- 企鹅的视觉基准是先前确认的**圆润幼态原创黑白企鹅**，橘黄嘴巴与脚、短翅膀、丰富表情、**无腮红**；此前生成的概念图是视觉参考，不能当成已存在的 SVG 资源。
- 场景拥有中央活动区、窗边、植物角、小窝、连接区域的隐形路径。环境物件为固定美术，不开发家具收集/摆放系统。
- 桌面建议窄侧栏导航；手机建议底部三入口导航。记录和回忆界面继续保留完整核心功能。
- 首页应突出企鹅，日记页专注输入与确认，不放常驻企鹅动画；回忆页继续支持历史浏览及现有编辑/纠正能力。

## 2. 已确认：日记原文与字数规则

- **日记正文不设产品人为字数上限**；不可在正式页面设置 `maxLength=1000`、`0/1000`、不可因视觉稿中的字符计数沿用 1000 字限制。
- AI 情绪识别的 API 体积/模型 token/字符保护上限独立于日记保存限制。AI 失败、超时、过长时提供**手动选择情绪并保存完整原文**的路线。
- 保存失败应保留原文、情绪选择、必要的待重试上下文，不能清空草稿；本地浏览器实际存储耗尽时如实提示。
- 不改写、截断、润色、总结或补全用户日记；仍由用户确认后保存。
- 正式页面不展示固定 1000 字分母；如未来增加计数，必须是不带上限暗示的实数字符计数（该计数并非 V1 必做）。

## 3. 已确认：爱心特效唯一触发条件

- **仅已确认并成功保存的 `EmotionReading.label === "joy"` 可以在这次保存后企鹅反馈中出现短暂爱心特效**。
- `calm`、`sadness`、`anxiety`、`anger`、`tired`、`mixed`、`neutral`、`unknown` 都不能出现爱心特效。
- 企鹅长期主导性格 `cheerfulness`（开朗）不是 `joy`，**不得仅因开朗主导就出现爱心特效**。用户呼唤、抚摸、观察等常规互动不得独立触发爱心粒子。其他非爱心表情与动作可以依规则正常播放。
- 手动确认 `joy` 与采纳 AI 建议并确认的 `joy` 同等待遇；**AI 只是建议但尚未保存，不触发**。
- `joy` 也不意味着必须长时间反复播放爱心；短暂、轻量、一轮反馈内至多一次，且要有低动态/隐藏页面降级。
- 配置上建议集中定义 `saveFeedbackEffectByEmotion`，仅 `joy` 项允许 `hearts`，其余为 `[]`；渲染层只能读取配置和已确认事件，不能自行根据 VAD 正负或猜测的用户状态生成爱心。

## 4. 已确认：页面导航、保存联动

- 日记与企鹅为两个页面，保存日记后**不强制跳转**。成功后留在日记页显示轻量确认与“回小屋看看”入口。
- 当用户主动回到小屋时，如果该次成功保存的反馈仍符合一次性展示条件，企鹅停下当前动作、看向用户、短暂回应后恢复生活。**反馈只发生在真实保存成功之后**。
- 现有 `AppState.lastConfirmedSave` 具有 `eventId`、`entryId`、`emotion`、`savedAt`；`useBehaviorRuntime` 已有 `save_feedback`、基础去重和 3000ms 配置。需要完善**跨页面返回时的一次性消费与过期策略**，不能简单重复启动、也不能改性格分数。
- 当重逢问候和保存反馈都待展示时，先保障重逢门控；两种展示不得叠加、重复。具体优先级、队列或放弃策略属于实施建议，写入开发任务卡后再验收。
- 刷新与多标签页、保存失败、浏览器后台及 React StrictMode 不得造成重复触发或计时器泄漏。

## 5. 已确认：绘本小屋活动范围与动作来源

- 固定绘本场景，**有限区域的自然连续移动**，不做大型自由寻路/开放地图。
- 五个活动区：中央、窗边、植物角、小窝、过渡路径。区域坐标应使用相对位置，兼容屏幕比例，保持脚底贴地和前后景遮挡合理。
- 继承现有 `src/config/behavior.ts` 的 27 个行为 ID 和规则；行为引擎负责“做什么”，新增的纯展示编排负责“去哪里、如何转身、如何表现动作”。禁止复制一套抽样/权重决策。
- 参考 Penguin-Pet 的步态/朝向/状态切换思路，参考 React Kawaii 的身体/面部 SVG 分层；参考 Kinder World 的治愈场景氛围；**不复制第三方角色与素材**，不引入 Electron 或运行时不必要依赖。
- 普通动作：待机、呼吸、眨眼、张望、走路、转身、坐下、休息、挥翅、观察、轻跳等；通过配置映射现有行为，复用基础动作而不是为每个 ID 建一套资源。
- 特殊行为 `drink` / `smoke` 的触发规则已于 2026-11-14 定稿（[COMPANION_SPEC](COMPANION_SPEC.md) §3.5），但其视觉属于阶段七独立开发包，不属于基础动作与主流程必做项。`specialBehaviorEnabled` 仍为 `false`；必须在特殊动作、道具与触发逻辑实现并验收后，由独立任务启用，**不得在 UI 整合中擅自开启**。
- 页面隐藏暂停调度与动画，恢复后以既有运行时规则重新选择；`prefers-reduced-motion` 时应静态或简化呈现，不能阻断功能。

## 6. 明确仅为候选：UI 动画与冲突细节

以下不是用户定稿参数，不可直接描述为已验收产品规则：

- 桌面侧栏/手机底栏断点，路由淡入时长（候选 150–250ms），场景宽高比、角色像素尺寸。
- 跨页面保存反馈有效期、连续多次保存仅保留最近一条的策略、互动与反馈相撞时的抢占规则。
- 企鹅响应分阶段具体毫秒数；可先沿用现有 `BEHAVIOR_V2.saveFeedbackDurationMs=3000`，视觉验收后调整。
- 爱心数、轨迹、透明度、持续时间；只能在已确认的 `joy` 条件下调试，不可为了艺术效果扩大触发范围。
- 小屋的原画色值、 SVG `viewBox` 与碰撞区域精确坐标；以人工视觉验收定稿。

## 7. 最小开发分包建议（不要求一次性全量重构）

1. **规范同步（仅文档）**：更新 `docs/STAGE7_DESIGN.md` §A/§C，补充已确认的首页/独立页面/绘本空间/无字数限制/仅 joy 爱心；更新 `docs/STAGE7_TASK_CARD.md` 的约束、验收与待确认参数。其他文档仅修正确有冲突的表述。
2. **企鹅原创视觉**：正式黑白企鹅 SVG、正侧背姿态、身体和表情部件；用单一共享角色资产保证一致性。
3. **动作表现**：现有行为 ID → 独立动作/锚点/动画配置 → SVG 展示，不改行为引擎的选取与权重。
4. **绘本场景**：固定小屋背景与中央/窗/植物/小窝锚点，支持有限移动，含可访问性及低动态回落。
5. **特殊行为视觉（独立验收包）**：在基础动作验收后制作 `smoke` / `drink` 姿态、临时香烟/酒杯道具与短暂烟雾/饮用表现；规则已定稿但 `specialBehaviorEnabled` 保持关闭，动画与触发逻辑验收后才由独立任务启用。道具不进入 V1 饰品/背包/装扮，不塞入九种表情。详见 [STAGE7_DESIGN](STAGE7_DESIGN.md) §A9。
6. **正式 UI**：调整路由为 `/` 小屋、`/diary` 日记、`/memories` 回忆，旧 `/companion` 兼容；页面之间不丢草稿、历史/纠正能力不丢。
7. **保存反馈整合**：确认保存成功→日记成功提示→返回小屋→一次性动作；效果仅 `joy` 可以出现爱心。核对隐藏、刷新、连存、重逢与失败情况。
8. **集中验收**：最小规则/运行时回归、typecheck/lint/build、桌面/手机人工主流程冒烟；不为此新增大量无关测试。

## 8. 关键验收场景

- [ ] 打开 `/` 直接进入企鹅小屋；`/diary` 专注写日记；`/memories` 浏览回忆；若采纳兼容建议，旧 `/companion` 可兼容访问。
- [ ] 企鹅正面、左右侧、背面一致，圆润黑白、橘黄嘴脚、无腮红；房间有绘本氛围且用户观察得到动作。
- [ ] 27 个现有行为各有合理视觉回落；五维主导行为风格可辨认，动作不改领域权重/分数。
- [ ] 日记可以超过 1000 字；不因 AI 输入超限而无法使用手选保存；长文不被截断。
- [ ] 保存失败无企鹅反馈、无正式状态改变；草稿不丢，允许重试。
- [ ] 成功保存 `joy` 后主动返回小屋：允许一轮轻微爱心效果；同事件不会重复播放。
- [ ] 成功保存除 `joy` 外的其他八类情绪：**任何情况下均没有爱心特效**，但仍可显示合适的企鹅动作。
- [ ] `cheerfulness` 为长期主导但本次保存 `sadness`：**没有爱心**；不会把开朗主导混同 `joy`。
- [ ] 仅 AI 建议为 `joy`、尚未保存：**没有爱心**。
- [ ] 久别重逢、互动、连存、刷新、隐藏恢复不出现重叠/循环/失控；低动态模式可用。
- [ ] 手机底栏与绘本场景适配，无场景位移溢出或关键功能被遮挡。
- [ ] V1 不出现服装、饰品、家具收集、商店、货币系统。
- [ ] 特殊行为未启用时 `smoke` / `drink` 不出现；独立验收包完成后也必须由独立任务启用，主流程与演示不依赖特殊行为。
- [ ] 抽烟/喝酒的香烟、酒杯仅作为临时道具，不出现在饰品、背包、库存或装扮入口，不鼓励模仿、不美化烟酒。

## 9. 交接时仓库状态与实施注意

截至交接稿编制时，`src/app/page.tsx` 仍指向日记 `HomeScreen`，`src/app/companion/page.tsx` 指向 `CompanionScreen`；`src/components/AppShell.tsx` 的导航与 `src/components/character/CharacterRenderer.tsx` 仍是临时实现。`EmotionDraftForm.tsx` 目前没有 `maxLength`，意味着 **1000 字上限问题主要来自概念稿**，开发时不可回填。

不能把视觉图里的角色、书本或场景图片视为仓库现成可使用资源。正式资产允许 AI 辅助创作，但须人工验收原创性、风格和版权边界。所有正式领域改动仍遵守 `AGENTS.md`：不扩大范围、不自行改性格规则、不增加 V2 系统。
