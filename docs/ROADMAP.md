## 3. 占位与真实实现边界

- 可用占位 / mock：C2 的契约 mock（明确标注为演示数据，走相同原生校验与映射路径）；C3 场景对象与动画可用原创简化 SVG 占位；C4 世界成长外观可用占位植物；C5 装饰外观可用明确标识的临时图形或现有图层占位，不宣称最终美术。
- 必须真实实现才能演示新版核心玩法：C1 性格计分与存档兼容、C3 自主行为选择与习惯计数、C4 九情绪共鸣与习惯形成、C5 装饰解锁/回收/再获得与历史。C2 必须交付真实百炼 Provider 接入能力；真实 Key 或账号能力不可用时交付手选闭环并如实注明真实 AI 未验通，不阻塞主线。
- 旧 XP 结算、旧「经验解锁装饰」与「消极情绪隐藏/恢复装饰」均不再作为现行规则或验收目标；旧存档字段只作兼容保留。是否把旧装饰数据映射进新目录待用户确认。
- 装饰的阈值、目录、槽位、穿戴方式与 C5 历史结构细节未确认（COMPANION_SPEC 第 11 节）；实现前由用户确认候选参数或明确授权按候选值开发，PR 标注「参数待验收」。

## 4. 分支任务卡约定

每阶段实施指令写明：前置提交、目标、允许改动模块、公共接口、禁止提前项、最小验收、暂不实现项。已有同任务分支或 PR 先检查再复用；不要一次启动后续全部功能分支，也不把未合入的接口假定为 main 已存在。

只有用户允许并完成前置合并后才进入下一阶段。跨阶段小缺口能在当前范围内用简化实现接上时直接完成并记录；需要改变产品方向或破坏契约时明确指出具体决定点。

允许集中审核多个待审 PR 以提高吞吐，但不得绕过真正的前置依赖：只有前置合入 main 后才启动依赖阶段，不改变禁止代理自动合并的规定。部署与验证安排：C2 开始前明确演示部署环境、服务端 Key 配置与接口预算保护方案（AI_CONTRACT 第 2.5 节），公开部署前保护必须有效；C6 负责最终部署体验与说明。

## 5. 完成判据

当前任务功能完整、必要最小冒烟通过（或明确外部限制与可用降级）、提交推送成功、唯一任务 PR 已创建，视为可交付待审核；是否合并由用户决定。不要把新增测试数量、全面覆盖率和反复全量回归作为阶段完成门槛。
