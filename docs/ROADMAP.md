## 3. 占位与真实实现边界

- 可用占位 / mock：C2 契约 mock（明确标注为演示数据，走相同原生校验与映射路径）；C3 场景对象与动画可用原创简化 SVG 占位；C4 世界成长外观可用占位植物。占位必须明确标识，不得宣称为最终玩法或真实接入。
- 必须真实实现才能演示新版核心玩法：C1 性格计分与存档兼容、C3 自主行为选择与习惯计数、C4 九情绪共鸣与习惯形成。C2 必须交付真实 TypeSafe HTTP Provider 接入能力；真实 Key 不可用时交付手选闭环并如实注明真实 AI 未验通，不阻塞主线。
- 旧 XP / 装饰隐藏结算默认不开发；待用户对 PRODUCT_SPEC 第 5 节候选方案作出最终取舍后另立任务，不在 C1–C5 中擅自实现。
- 未决参数（COMPANION_SPEC 第 10 节）不阻塞 G1；C1 启动前由用户确认候选参数或明确授权按候选值开发（PR 标注「参数待验收」）。

## 5. 分支任务卡约定

每阶段实施指令写明：目标、允许改动模块、依赖提交、公共接口、最小验收、暂不实现项。已有同任务分支或 PR 先检查再复用（U1 已复用 PR #5 完成，不重复建 PR）。不要一次启动后续全部功能分支，也不把未合入的接口假定为 main 已存在。

只有用户允许并完成前置合并后才进入下一阶段。跨阶段小缺口能在当前范围内用简化实现接上时直接完成并记录；需要改变产品方向或破坏契约时明确指出具体决定点。

允许集中审核多个待审 PR 以提高吞吐，但不得绕过真正的前置依赖：只有前置合入 main 后才启动依赖阶段，不改变禁止代理自动合并的规定。部署与验证安排：P1 已固定 Node 版本要求、包管理器、锁文件与验证脚本；C2 开始前明确演示部署环境、服务端 Key 配置与接口预算保护方案（AI_CONTRACT 第 2.5 节），公开部署前保护必须有效；C5 负责最终部署体验与说明。

## 6. 完成判据

当前任务功能完整、必要最小冒烟通过（或明确外部限制与可用降级）、提交推送成功、唯一任务 PR 已创建，视为可交付待审核；是否合并由用户决定。不要把新增测试数量、全面覆盖率和反复全量回归作为阶段完成门槛。
