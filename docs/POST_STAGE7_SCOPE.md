## A. 已确认的许愿屋产品行为

1. 用户可以亲自写下愿望，并将它保存到「许愿屋」。
2. 未完成愿望显示为透明**玻璃杯中的纸团**；纸团必须对应已保存、未完成的真实愿望。
3. 愿望完成由用户手动标记；完成后纸团**飘升并变成星星**，星星代表已完成的真实愿望。
4. 保存与完成状态需要可靠持久化，刷新页面后不能恢复为不存在的愿望或未完成状态；若保存失败，必须告知用户，不能播放“完成成功”动画。
5. 愿望不影响日记原文、情绪确认、五维性格分数、主导性格、离线生活及久别重逢；不生成或伪造情绪日记。
6. 未完成愿望不触发处罚或催促。AI 不得自行判定、写入或完成愿望。

- **候选路由**：`/wishes`。现有 `/` 小屋、`/diary` 日记和 `/memories` 回忆保持不变；第四入口的桌面与手机视觉位置已于 2026-11-16 确认（[基线](WISH_HOUSE_VISUAL_APPROVED.md)），路由仍待实现阶段最终确定。

- **候选企鹅联动**：看向杯子或星星、轻挥翅；以已有视觉和互动能力为主，避免扩张 27 个既有行为 ID、行为权重或新增持久计分事件。

## C. 未来开发工程边界（方案待任务卡评审）

- 建立独立 `Wish` 数据边界，建议字段：`id`、`text`、`status`（`pending`/`completed`）、`createdAt`、`completedAt`。字段和具体存储方式须在任务卡中评审。
- 优先评估独立、可版本化的愿望存储适配器，避免为了独立功能无必要地改写正式 `Snapshot` v4 和性格事件逻辑；如果确需修改正式存档，必须先更新 `ARCHITECTURE`、设计迁移与失败恢复方案，获批准后实施。
- 保存及完成必须以持久化成功为准；读写异常、损坏数据、额度不足时显示恢复提示，不覆盖用户现有日记。
- 所有愿望文本按纯文本渲染，禁止执行用户输入中的 HTML/脚本；不将私人愿望传给 AI 服务或外部服务器。
- 模块应分清愿望规则、存储适配、只读展示和动画四类职责。不得把愿望关联到 `EmotionReading`、`PersonalityContribution`、`BehaviorDecision` 或 `ReunionState` 的计算。

## D. 最小验收

- 首次创建一个愿望 → 在杯中出现对应纸团 → 刷新仍存在且状态正确。
- 手动完成该愿望 → 该纸团不再属于未完成集合 → 出现对应星星 → 刷新仍保持完成。
- 没有愿望时提供真实空状态；多个愿望时所有文本仍可访问，视觉对象不越界。
- 未完成和已完成统计与真实数据一致，不凭空添加示例愿望。
- 保存失败或存储不可用时，保留输入、准确提示；不能出现“成功变星星”假象。
- 既有日记记录、编辑、纠正、五维台账、重逢、保存反馈无变化；无 Key 时手选情绪仍可用。
- 窄屏、键盘、低动态模式可用；星星视觉不妨碍基本阅读。

2. **交付位置**：PR #38 验收合入 `main` 后独立补充开发，建议分支 `feature/memories-pagination`，在阶段八开始前完成并验收；不得回写 PR #38，也不得把本包作为 PR #38 的验收条件变更。
3. **行为边界**：翻页只改变阅读呈现，不改变日记原文、情绪、纠正记录与时间顺序；历史编辑、情绪纠正、长文阅读与低动态降级能力必须保留。
4. **最小验收**：多条记录可真实前进/后退翻页；首末页边界行为明确；刷新或重新进入后数据不丢失；键盘可翻页；低动态模式下以静态切换代替翻页动效；大量记录不会一次性渲染造成明显卡顿。
5. **待确认参数**：每页记录数、翻页视觉样式（页码/书签/手势）与是否记忆上次阅读位置，在视觉验收中确定；不得反推修改已验收三页视觉基线。

## F. 赛前候选增强（均非新增功能开发授权）

1. **企鹅便笺**：仅在既有一次性保存反馈条件满足时，以本地审核过的简短文案增强陪伴感；不新增 AI 对话权限，不新增评分和存档副作用。
