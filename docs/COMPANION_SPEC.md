# 拾绪 ShiXu · 性格与行为详细规格 v3

> 本文是性格评分、性格描述、自主行为与互动的**唯一详细事实来源**。产品范围见 [PRODUCT_SPEC](PRODUCT_SPEC.md)，接口与存档见 [ARCHITECTURE](ARCHITECTURE.md)。
>
> 状态标记：
> - **已确认**：用户已明确并要求执行，不得擅自改动。
> - **候选**：本文给出的默认值，可直接按此实现，但必须在 PR 标注「参数待验收」。
> - **待确认**：必须先获得用户确认才能定稿；实现时可采用本文候选值，但不得宣称已获批准。
>
> V1 的全部数值都是候选或待确认；旧指南中已获授权的三维护账参数（`companion-v1`）只用于理解现状，不再作为新引擎的依据。

## 1. 职责边界

| 机制 | 负责 | 不负责 |
| --- | --- | --- |
| 情绪确认 | 九类情绪、VAD、强度、来源、手动纠正 | 不直接加性格分 |
| 性格引擎 | 长期台账、五维派生分数、自然语言描述、只读查询 | 不选择动作、不渲染 |
| 行为选择 | 依据只读性格、当前情绪、互动、时间与种子选择行为 | 不改性格、不写存档 |
| 互动反馈 | 即时反应与保存后一次性情绪表现 | 不产生持久奖励、不刷分 |
| 角色展示 | 按 `CharacterView` 渲染表情、姿态、图层 | 不判定性格、不写存档 |

原则（**已确认**）：

- 性格由长期情绪记录逐渐形成，不是当前心情的复制。
- 单次情绪不造成性格剧变；性格可双向缓慢变化。
- 悲伤、焦虑、愤怒是正常情绪，不是人格缺陷，也不是惩罚对象。
- 用户看不到精确分数，只看自然语言描述与行为差异。
- 所有结算由确定性纯函数完成；时间、日期键与随机种子由应用层显式传入。
- AI 不参与性格计分、行为选择或存档修改。

## 2. 性格系统

### 2.1 维度（候选五维，名称待确认）

| ID | 中文 | 行为含义 | 不得表述为 |
| --- | --- | --- | --- |
| `liveliness` | 活泼 | 精力外放、愿意主动发起互动、动作幅度大 | 吵闹、坐不住 |
| `courage` | 勇敢 | 愿意先尝试、面对陌生场景不退缩 | 鲁莽、逞强 |
| `gentleness` | 温柔 | 回应柔和、愿意先照顾对方感受 | 软弱、讨好 |
| `sensitivity` | 敏感 | 对细节和情绪变化察觉快、反应细腻 | 脆弱、玻璃心、神经质 |
| `curiosity` | 好奇 | 对新事物、新角落、新玩法有兴趣 | 多动、不专注 |

五维均为连续倾向，不分好坏，不构成人格类型判定。维度 ID 与文案由 `PersonalityRuleConfig` 提供，新增/改名不得散落在组件中。

### 2.2 九类情绪的基础影响（候选）

数值为**基础增量**，尚未乘强度、惯性与上下限：

| 情绪 | 活泼 | 勇敢 | 温柔 | 敏感 | 好奇 | 设计意图 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 喜悦 `joy` | +2 | +1 | +1 | -1 | +1 | 更外放、更愿意尝试 |
| 平静 `calm` | -1 | 0 | +2 | +1 | 0 | 更柔和、更安定 |
| 难过 `sadness` | -1 | 0 | +1 | +2 | 0 | 更细腻、更需要陪伴 |
| 焦虑 `anxiety` | -1 | -1 | 0 | +2 | +1 | 更敏锐，也更谨慎 |
| 生气 `anger` | +1 | +2 | -1 | +1 | 0 | 更直接、更有边界 |
| 疲惫 `tired` | -1 | 0 | +1 | +1 | 0 | 更安静、更愿意休息 |
| 复杂 `mixed` | 0 | 0 | +1 | +1 | +1 | 感受层次更多 |
| 一般 `neutral` | 0 | 0 | 0 | 0 | 0 | 日常中性记录 |
| 未知 `unknown` | 0 | 0 | 0 | 0 | 0 | 未识别，不参与成长 |

约束（**已确认**）：

- 每类情绪至少影响一个维度；负面情绪不得整体为负，也不得把任何维度长期压向下限。
- 单条记录不会同时把多个维度大幅拉低；负向增量只用于表达倾向差异，不构成惩罚。
- 具体数值是候选参数，必须集中在配置中，不得写在组件里。

### 2.3 强度、惯性与边界（候选）

| 参数 | 候选值 | 说明 |
| --- | --- | --- |
| 初始分 | 50 | 五维一致的中性起点 |
| 下限 / 上限 | 20 / 80 | 分数只在区间内变化 |
| 单次结算上限 | ±3 | 乘完强度与惯性后截断 |
| 单日单维净变化上限 | ±4 | 同一天所有记录（含纠正）合计 |
| 强度分档 | `<0.35 → ×0.5`；`0.35–0.7 → ×1`；`>0.7 → ×1.5` | 使用 `intensity` |
| 惯性系数 | `1 - 距初始值的偏移 / 到该方向边界的距离` | 越接近边界越难继续同向变化 |
| 描述分档 | `≤42` 低；`43–57` 均衡；`≥58` 高 | 只用于选文案，不展示数字 |

单次计算（确定性，无随机）：

```text
intensityFactor = 按上表分档
roomFactor      = 正增量: 1 - (current - initial) / (max - initial)
                  负增量: 1 - (initial - current) / (initial - min)
applied         = round(base × intensityFactor × roomFactor)
applied         = clamp(applied, -3, +3)
```

- `current` 是该维度**当前派生分**（初始分 + 已结算增量之和，clamp 后），不单独存储第二份分数。
- `roomFactor` 在初始分处为 1，在边界处为 0；四舍五入后为 0 时不产生增量。
- 单日上限：把当天同一维度的已结算增量求和后截断到 ±4；超出部分不补记、不顺延。
- 单次上限与单日上限同时生效，取更严格者。

### 2.4 结算与保存契约（方向已确认，数值候选）

1. 只有**已确认情绪**进入结算：手动选择、用户确认后的 AI 建议、用户纠正后的情绪。
2. 每条日记最多对应一条贡献，键为 `entryId`；贡献记录 `dayKey`、`label`、`entryRevision`、`deltas`、`rulesVersion`。
3. 性格分数不落盘，由台账纯派生；读取时按当前 `PersonalityRuleConfig` 计算。
4. 同一次保存只结算一次；`eventId` 重复直接返回未变化，不重复计分。
5. 保存失败不产生贡献，不更新界面状态；重试复用冻结的 `eventId`、`entryId`、`time`、`dayKey`。
6. `dayKey` 使用保存时应用层提供的本地日期，之后不再改变；跨天补记按当时保存日期计算。
7. 编辑正文不改变情绪、不重算贡献、不改变 `dayKey`。
8. 纠正情绪替换原贡献：沿用原 `dayKey` 与原规则的 `rulesVersion` 重算，不叠加、不追回其他日期已产生的变化。
9. 旧规则版本的贡献在配置仍可取得时按该版本重算；配置不可得时保留原贡献并按当前版本读取，但在存档中保留版本标识，不静默改写。
10. 迁移不追溯旧日记：v2→v3 时旧三维护账进入 `legacy`，新五维从初始分开始（是否换算待确认）。

### 2.5 性格查询（只读）

性格模块对外只提供：

- `derivePersonality(state, config): PersonalitySnapshot`：返回五维分数、描述、规则版本。
- `describePersonality(snapshot): PersonalityDescription`：返回页面可直接展示的自然语言，不含数字、百分比、等级或诊断结论。
- `getDimensionScore(snapshot, id)`：供行为模块按阈值读取倾向。

行为模块、角色模块与 V2 饰品模块只能读取 `PersonalitySnapshot`，不得写入 `PersonalityState`。

### 2.6 VAD 分工（已确认）

- `label` 是性格结算的主依据，避免「标签 + 维度」重复计分。
- `intensity` 只缩放幅度，见 §2.3。
- `valence` / `arousal` / `dominance` 不进入性格增量，用于即时表情、动作幅度与行为偏好（§3.4）。
- `confidence` 只用于提示「建议复核」，不参与任何计分。

### 2.7 用户可见描述（候选文案）

描述按维度分三档，可组合成一到两句自然语言；不得出现分数、排名、诊断或「异常」措辞。

| 维度 | 低（≤42） | 均衡（43–57） | 高（≥58） |
| --- | --- | --- | --- |
| 活泼 | 最近比较安静，喜欢慢慢来 | 动静之间比较平衡 | 精力充沛，常主动凑过来 |
| 勇敢 | 面对新事物会先观察一会儿 | 需要时会往前一步 | 愿意先尝试，不太怕陌生 |
| 温柔 | 表达直接，边界清楚 | 温和，也保留自己的分寸 | 习惯先照顾别人的感受 |
| 敏感 | 不太容易被细节打扰 | 能察觉变化，也能放下 | 对细小的变化很敏锐，感受细腻 |
| 好奇 | 更偏爱熟悉的事物 | 对新鲜事保持适度兴趣 | 总想看看接下来会发生什么 |

页面可展示「它最近的样子」而非「性格评分」。描述文案属于候选，可调整措辞，但不得引入价值判断。

### 2.8 规则版本与兼容

- 配置常量 `PERSONALITY_RULES_VERSION = "personality-v1"`，与维度、评分表、边界、描述文案一起版本化。
- 调整任何数值或维度都必须升版本，并在 [ARCHITECTURE](ARCHITECTURE.md) §4 记录存档影响。
- 同一 `rulesVersion` 的配置必须保留在代码中，供纠正旧记录时重算；不得只保留最新版本。
- 旧 `companion-v1`（三维护账）只读兼容，不再产生新贡献。

### 2.9 最小验收（性格）

1. 同一 `eventId` 重复提交，分数与台账不变。
2. 同一天连续记录多次，单维净变化不超过 ±4，且不出现负分越界。
3. 编辑正文后，贡献、`dayKey`、分数不变。
4. 纠正情绪后，该条贡献被替换；描述随分数变化；其他日期不变。
5. 保存失败时，性格台账与界面状态都不变。
6. 五维描述不包含数字、等级、诊断词；`敏感` 不出现「脆弱」等贬义表述。
7. v2 存档迁移到 v3 后，日记正文、情绪、纠正、历史逐字保留；旧台账进入 `legacy` 且不参与新分数。

## 3. 自主行为

### 3.1 行为集合（候选）

| ID | 中文 | 表现 | 基础权重 |
| --- | --- | --- | ---: |
| `idle` | 发呆 | 原地站立、轻微呼吸/漂浮 | 30 |
| `stroll` | 散步 | 在场景内缓慢移动 | 25 |
| `rest` | 休息 | 坐下或蜷起，动作幅度小 | 15 |
| `explore` | 探索 | 走向场景边缘/物件，东张西望 | 15 |
| `play` | 玩耍 | 原地跳跃、转圈、挥手 | 15 |

五种行为是 V1 的完整集合。新增行为只需扩展 `BehaviorRuleConfig` 与动作映射，不修改性格算法。

### 3.2 配置结构（`BehaviorRuleConfig`）

```ts
interface BehaviorRuleConfig {
  rulesVersion: string;              // "behavior-v1"
  behaviors: BehaviorDefinition[];   // id、名称、基础权重、动作/表情映射
  dimensionWeights: DimensionWeightRule[]; // 维度阈值 → 行为加权
  emotionWeights: Record<EmotionLabel, Partial<Record<BehaviorId, number>>>;
  timeWeights: Record<TimeBand, Partial<Record<BehaviorId, number>>>;
  minShare: number;                  // 每种行为最低占比，候选 0.05
  maxConsecutive: number;            // 同一行为最多连续次数，候选 2
  tickIntervalMs: [number, number];  // 候选 [20000, 40000]
  interactionDurationMs: [number, number]; // 候选 [2500, 4000]
}
```

所有阈值与加权都在配置中；组件不得写死行为映射或情绪映射。

### 3.3 选择算法（确定性）

输入 `BehaviorContext`：

```ts
interface BehaviorContext {
  personality: PersonalitySnapshot;   // 只读
  emotion: EmotionReading | null;     // 当前已确认情绪
  interaction: InteractionEvent | null; // 显式互动，运行时有值
  dayKey: string;
  timeBand: TimeBand;                 // morning/afternoon/evening/night
  sequence: number;                   // 应用层递增序号
  seed: number;                       // 应用层显式提供
  lastBehaviorId: BehaviorId | null;
  consecutiveCount: number;
}
```

步骤：

1. 基础权重取自配置。
2. 按性格维度阈值加减权：高（≥58）或低（≤42）才触发，避免频繁抖动。
3. 叠加当前情绪权重、时间段权重。
4. 若有显式互动，跳过加权选择，直接返回互动反应行为。
5. 归一化前保证每种行为至少 `minShare`；不足时抬到下限并重新归一化一次。
6. 用 `seed` 做确定性加权抽样（同一上下文必须得到同一结果）。
7. 若结果与 `lastBehaviorId` 相同且 `consecutiveCount >= maxConsecutive`，按权重顺序取下一个非重复行为（确定性，不用随机重抽）。

输出 `BehaviorDecision`：

```ts
interface BehaviorDecision {
  behaviorId: BehaviorId;
  pose: PoseId;
  expression: ExpressionId;
  durationMs: number;
  reasonCode: string;   // 可解释来源：dimension/emotion/time/interaction/fallback
}
```

候选加权（可调，均属候选参数）：

| 来源 | 规则 |
| --- | --- |
| 活泼高 | `play +15`、`stroll +10`；活泼低 | `idle +10`、`rest +10` |
| 勇敢高 | `explore +15`、`play +5`；勇敢低 | `idle +5` |
| 温柔高 | `idle +10`、`rest +10`；温柔低 | `explore +5` |
| 敏感高 | `idle +10`、`rest +5`；敏感低 | `play +5` |
| 好奇高 | `explore +20`、`play +10`；好奇低 | `idle +10` |

### 3.4 当前情绪与表现（候选）

| 情绪 | 行为偏向 | 表情 |
| --- | --- | --- |
| 喜悦 | `play +20`、`stroll +10` | 眉眼弯起、轻微跳动 |
| 平静 | `idle +15`、`rest +10` | 放松、缓慢呼吸 |
| 难过 | `rest +15`、`idle +10` | 眉眼低垂、动作小 |
| 焦虑 | `idle +15`、`stroll +5` | 视线游移、手指微动 |
| 生气 | `stroll +20`、`play +5` | 眉头收紧、动作直接 |
| 疲惫 | `rest +30`、`idle +10` | 眼皮下沉、动作慢 |
| 复杂 | `explore +10`、`idle +5` | 表情中性偏困惑 |
| 一般 / 未知 | 不加权 | 默认平静 |

`valence` 控制表情明暗方向，`arousal` 控制动作幅度，`dominance` 控制视线与朝向；三者只影响表现，不影响性格。`intensity` 缩放动画幅度，低强度不做夸张动作。

### 3.5 互动（V1 基础互动，候选）

| 互动 | 触发 | 反应 |
| --- | --- | --- |
| `call` 呼唤 | 点击角色/呼唤按钮 | 转向用户、看向镜头，1 次点头或挥手 |
| `pat` 摸摸头 | 点击头部区域（若已实现命中区） | 闭眼/弯眼，轻微下沉，持续 2.5–4 秒 |
| `observe` 凑近看看 | 打开陪伴页停留 | 若距离近，回望一次，不产生持久效果 |

约束（**已确认**）：

- 互动只产生运行时反馈，不写性格台账、不增加分数、不形成持久奖励。
- 互动可打断当前自主行为，播完回到行为调度。
- 互动事件必须由应用层显式创建，带 `id`、`type`、`occurredAt`、`seed`；不得依赖隐式 `Date.now()` 或 `Math.random()`。
- 互动不给 AI 提供任何控制动作的入口。

### 3.6 生命周期与离线边界（已确认）

- 页面隐藏（`document.visibilityState === "hidden"`）时暂停调度与动画；恢复可见后从当前上下文继续。
- 关闭网页不模拟离线生活、不累积离线时间、不补播行为、不产生离线成长。
- 刷新后行为序号与种子可以重置；V1 不持久化行为结算。
- 尊重 `prefers-reduced-motion`：减少位移与循环动画，保留静态表情。

### 3.7 行为模块不写存档

V1 中 `BEHAVIOR_SETTLED`、`INTERACT` 不是持久化事件，仅作为运行时 `BehaviorDecision`/反馈存在。行为结果不需要 `eventId` 幂等，因为它不改变正式状态。若未来需要跨刷新保持行为历史，必须新增独立事件与迁移方案，不得偷偷写入现有字段。

### 3.8 最小验收（行为）

1. 相同 `BehaviorContext` 多次调用得到相同 `BehaviorDecision`。
2. 每种行为长期占比不低于 5%；同一行为不连续超过 2 次。
3. 更改性格快照（只读输入）会改变偏好分布，但行为模块不修改快照。
4. 页面隐藏后不再产生新决策；恢复可见后继续。
5. 互动反应不改变性格台账与分数。
6. 关闭再打开页面不出现「离线经历」或补算。

## 4. 角色表现

- 角色展示层只接收 `CharacterView` 与可选外观配置，输出 SVG/React 渲染。
- `CharacterView` 至少包含 `expression`、`pose`、`animation`、`visibleLayerIds`、`effects`，V1 预留可选 `appearance`。
- 图层白名单之外的 ID 必须忽略并回落到基础形象，不得因未知图层崩溃。
- 原创全白小人基础形象是 V1 交付内容；正式视觉风格在阶段五由用户确认，不得提前美化或重设计其他页面。

## 5. V2 饰品边界（仅规划）

- V2 饰品模块可以读取 `PersonalitySnapshot` 与已落盘领域事件，自行维护饰品状态与解锁历史。
- V2 只能通过 `CharacterView.appearance` 的图层白名单叠加外观，不得写 `PersonalityState`、不得改分数、不得改行为规则。
- V1 不实现饰品目录、阈值、槽位、穿戴、回收、再获得或任何装扮 UI。
- V2 接入时新增独立 `GameEvent`/存档字段与迁移，不复用旧 `DecorationState` 字段执行业务。

## 6. 参数维护与验收

- 本文所有候选参数集中在 `PersonalityRuleConfig` / `BehaviorRuleConfig`，不得散落在组件或应用服务中。
- 修改参数必须：升规则版本 → 更新本文 → 更新受影响验收 → 在 PR 标注「参数待验收」。
- 涉及存档结构的修改必须先更新 [ARCHITECTURE](ARCHITECTURE.md) §4、§6 与迁移测试方案。
- 任何「已确认」标记的规则不得由开发代理自行调整；发现问题应报告影响与建议。
