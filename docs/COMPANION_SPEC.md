# 拾绪 ShiXu · 伙伴养成详细设计 v2

本文件是详细养成设计的唯一事实来源：集中定义隐藏性格评分表与参数、习惯形成、自主行为、即时共鸣、活动空间与共同回忆。[PRODUCT_SPEC](PRODUCT_SPEC.md) 只概述规则并引用本文件；状态模型与接口见 [ARCHITECTURE](ARCHITECTURE.md)；情绪字段与确认协议见 [AI_CONTRACT](AI_CONTRACT.md)；阶段安排见 [ROADMAP](ROADMAP.md)。

数值与文案参数除明确标注「已确认」外，均为**候选设计参数，待用户确认**，不代表已经过最终验收，也不代表心理学规律。数值只在本文件维护，其他文档与领域配置引用本文件，不复制数值表。落地时对应配置版本标记 `companion-v1`，调参只改本文件与配置版本，不追溯扣除已记录成长。

## 1. 四种机制的职责边界

| 机制 | 输入 | 输出 | 不负责 |
| --- | --- | --- | --- |
| 情绪识别 | 日记正文（仅用户主动发起） | AI 情绪建议（label / VAD / intensity / confidence），必须经用户确认 | 性格分数、角色动作、任何存档写入 |
| 即时共鸣 | 成功保存的确认情绪 | 一次短暂角色反馈与可选环境反馈 | 长期性格、习惯、永久情绪锁定 |
| 隐藏性格 | 确认且成功持久化的 EmotionReading.label | 三个维度的隐藏分数变化（确定性规则） | 即时动画选择、用户可见数值 |
| 自主生活 | 性格、习惯、环境、显式时间与随机种子 | 日常行为选择与习惯积累 | 情绪识别、模型决策 |

四者相互关联：识别 → 用户确认 → 即时共鸣（短暂）+ 隐藏性格贡献（长期）；性格影响自主行为权重，长期自主活动形成习惯，习惯再影响行为；所有情绪都留下回忆与世界成长痕迹。职责不得混淆：AI 只产建议；共鸣不写性格；性格不直接选动画；行为系统不调用模型。

## 2. 隐藏性格系统

### 2.1 维度（方向已确认）

首版三个内部维度，互相独立，不强行归类为互斥职业或人格类型：

| 维度 | 内部键名 | 影响倾向 |
| --- | --- | --- |
| 探索欲 | exploration | 探索、观察、散步 |
| 静心度 | serenity | 休息、发呆、安静活动 |
| 亲近倾向 | affinity | 主动靠近、打招呼、社交互动 |

用户不能查看精确分数，不能手动分配属性点，不能选择指定培养路线。角色资料只展示自然语言描述与已经形成的习惯标签。性格分数不是健康指标、心理诊断或用户人格分析；描述文案只描述小白人的行为倾向，不得评价用户本人。

### 2.2 情绪基础评分表（候选参数，待用户确认）

用户通过手动选择或 AI 建议，最终确认九种心情之一；系统在**成功保存后**按确认的 label 计算隐藏分数变化：

| 情绪 | 探索欲 | 静心度 | 亲近倾向 |
| --- | ---: | ---: | ---: |
| joy 开心 | +2 | -1 | +1 |
| calm 安心 | -1 | +2 | +1 |
| sadness 悲伤 | -1 | +1 | +2 |
| anxiety 焦虑 | +1 | -2 | +1 |
| anger 愤怒 | +2 | -2 | -1 |
| tired 疲惫 | -2 | +2 | 0 |
| mixed 复杂 | +1 | 0 | +1 |
| neutral 平常 | 0 | +1 | 0 |
| unknown 说不清 | 0 | 0 | 0 |

约束：

- 这是候选设计参数，不代表心理学规律；最终数值待用户确认。
- 负数只代表行为倾向减少，不是惩罚；分数边界（§2.3）保证不会出现极端负面人格。
- 悲伤、愤怒等情绪不得造成小白人讨厌用户、永久失去能力或变成负面人格。
- 保留全部九种情绪，不只区分积极/消极；unknown 零变化表达「说不清也被接纳」。
- 用户没有选择心情或未成功确认保存时，不得改变性格。
- 情绪来源 manual / ai / corrected 不改变相同确认 label 的基础评分；confidence 不作奖励倍数；VAD / intensity 不参与性格基础评分。

### 2.3 边界参数（候选，待用户确认）

- 初始分数：每维 50。
- 上下限：每维 20–80。
- 单日变化上限：每个 dayKey 每个维度的净变化绝对值不超过 6（候选值）。
- dayKey 沿用 P1 契约：首次确认提交时按浏览器当日本地日历生成 YYYY-MM-DD 并冻结；同一次操作保存失败重试复用原值，跨午夜不重新归日；新建另一条记录才使用新的当日 dayKey。

### 2.4 计分与保存契约（方向已确认，数值候选）

- 只有正式确认且成功持久化的日记才产生性格贡献；AI 建议未确认时不计分；保存失败不改变任何正式状态（含性格）。
- 采用按 entryId 追踪有效贡献的台账：每条贡献记录 `{entryId, dayKey（该日记冻结值）, label, deltas（经单日上限截断后的实际应用值）, entryRevision}`。台账是性格的唯一事实来源。
- 分数是纯派生值：每维 `score = clamp(初始分 + Σ 台账 deltas, 下限, 上限)`。台账确定则分数可复现，不单独维护第二份可漂移的分数存档。
- 幂等：沿用 eventId + appliedEventIds 与 entryId 唯一约束；重复提交、保存失败重试、刷新不得重复计分。
- 同一日多次记录受单日上限约束；超出部分仍可保存日记、产生共鸣与回忆，仅性格变化被截断。
- 日记正文编辑（EDIT_ENTRY_TEXT）不改变性格贡献。
- 用户主动纠正已保存心情（CORRECT_EMOTION）时，**替换**该 entryId 的台账贡献，不额外叠加：新 deltas 按新 label 查表，以「当日该维度合计减去该条旧贡献后的余量」重新截断；dayKey 仍用该日记原冻结值，跨日期纠正不重新归日；只修订被纠正条目，不级联重算同日其他条目。旧记录纠正同样修订性格贡献，但不覆盖最新记录的当前情绪与视觉（沿用 P1 契约）。纠正是贡献修订，不是惩罚：不删除日记、回忆、习惯或世界成长，不追回已形成的习惯。
- 原子提交：性格台账与日记、回忆、Snapshot 同一次整体保存；存储成功才生效。性格、习惯、回忆和存档保持一致的提交边界。
- 历史重算：默认不追溯旧日记（见 §10 待确认）；仅新规则启用后确认的日记计分。如需重算，只能由确定性纯函数从台账重建分数，不得引入数据库或复杂事件溯源系统。
- 性格计算必须是确定性、可复现的；领域函数不读 Date.now、Math.random 或外部副作用，时间与种子由应用层显式提供。

### 2.5 用户可见层（文案候选）

自然语言描述由内部部分数区间映射（候选三段：低 / 均衡 / 高），文案只描述小白人行为倾向（如「最近更爱到处看看」「最近喜欢安静待着」），不展示数字、进度条或评分表。习惯标签来自已经形成的习惯（§5）。文案区间与词表在 C1/C4 落地时细化，标注候选。

### 2.6 与 VAD 的分工（已确认）

- label：隐藏性格基础评分与即时共鸣变体选择的主要依据。
- VAD / intensity：即时情绪共鸣的表情细节、动作强弱与部分环境表现。
- AI confidence：仅用于识别结果提醒和确认，不直接作为性格奖励倍数。

该分工同步于 PRODUCT_SPEC、AI_CONTRACT 与 ARCHITECTURE；旧版「所有规则只按 VAD 判断」的绝对表述已废止。

## 3. 即时情绪共鸣

触发规则已确认：用户成功确认心情并保存后，小白人立即作出一次轻量反馈；九种情绪都有不同且温和的表现。表现示例为候选，落地时可按素材能力微调，但九种区分与温和基调已确认：

| 情绪 | 共鸣表现（候选示例） |
| --- | --- |
| joy 开心 | 轻快蹦跳 |
| calm 安心 | 安静舒展 |
| sadness 悲伤 | 安静陪伴 |
| anxiety 焦虑 | 短暂停顿后舒缓 |
| anger 愤怒 | 轻微活动后放松 |
| tired 疲惫 | 坐下休息 |
| mixed 复杂 | 观察周围 |
| neutral 平常 | 继续普通生活 |
| unknown 说不清 | 好奇地歪头 |

- label 决定共鸣变体；VAD / intensity 在有限范围内调制幅度、特效透明度与表情细节，不无限放大，不影响永久扣减。
- 即时共鸣只是短暂反馈，结束回到自主生活，不永久锁定角色情绪。
- 消极情绪不得造成惩罚、扣除已拥有物品或清除成长记录。
- 角色动作由本地确定性规则选择；AI 不能直接选择动画、操控角色或修改存档。
- 环境反馈：不同确认情绪可产生不同的短暂场景效果（候选示例：开心→柔和光点，悲伤→安静细雨，疲惫→光线变柔和）；具体效果目录在 C4 细化并标注候选。所有情绪都可以留下成长与回忆痕迹。
- prefers-reduced-motion 下静态显示同一情绪，不播放位移/跳动动画。

## 4. 自主生活系统

### 4.1 基础行为（五种已确认）

发呆（gaze）、散步（walk）、休息（rest）、探索（explore）、玩耍（play）。小白人能在用户不操作时自主活动。行为可带可选目标对象（花朵、树荫、蝴蝶、用户等）；目标目录首版候选，随场景实现细化，不提前冻结地图结构。

### 4.2 选择与调度规则

- 采用轻量有限状态机：选择 → 执行 → 完成或被打断 → 重新选择。同时只允许一个主要角色行为执行。
- 权重 = 基础权重（候选均等）× 性格影响 × 习惯加成。性格映射候选：探索欲高→散步/探索/玩耍权重上升；静心度高→休息/发呆上升；亲近倾向高→靠近用户、打招呼变体上升。具体权重函数在 C3 落地，标注候选。
- 不同自主行为都保留最低出现机会（候选：每种行为不低于 5%）；不允许任何性格把角色永久锁定为某一种行为。
- 避免连续机械重复：同一行为不连续出现超过 2 次（候选，运行时最近序列约束）。
- 优先级：用户互动与新确认的情绪共鸣优先于普通自主行为，可打断当前行为；被打断的行为不计入习惯积累；动作结束后重新进入自主选择。
- 可复现随机：应用层显式提供 now、dayKey 与随机种子（如 dayKey + 存档 revision + 递增序号的稳定散列）；领域选择函数为纯函数，正式领域状态更新不得直接依赖隐式 Date.now、Math.random 或不可控外部副作用。

### 4.3 在线与离线边界（已确认）

- 浏览器页面隐藏时（visibilitychange）暂停不必要的动画与调度；恢复可见后重新选择，不补算隐藏期间的行为。
- 关闭网页后不模拟持续在线的真实生活，不产生虚构的离线行为经历；重新打开从当前存档状态重新选择。
- 无离线衰减、无离线习惯积累、无离线性格变化。

### 4.4 行为结算与习惯计数

行为完整执行完成后，应用层提交 BEHAVIOR_SETTLED 领域事件（稳定 eventId + 显式 now/dayKey）；规则按单日上限决定是否计入习惯进度；无变化则不写存档，避免写放大。刷新或被打断不计数（候选：完成才计数，防止刷新刷取）。事件与存档边界见 [ARCHITECTURE](ARCHITECTURE.md)。

## 5. 长期习惯形成

**性格 = 情绪积累产生的长期行为倾向；习惯 = 小白人长期自主活动形成的偏好。** 两者独立建模；习惯不直接修改性格分数，互动也不能直接刷性格。

### 5.1 五种候选习惯（名称与阈值待用户确认）

| 候选习惯 | 关联行为与目标 |
| --- | --- |
| 喜欢观察花朵 | 探索 / 散步 · 花朵对象 |
| 喜欢树荫 | 休息 · 树荫对象 |
| 爱看蝴蝶 | 探索 / 玩耍 · 蝴蝶对象 |
| 喜欢独自发呆 | 发呆（无目标） |
| 偶尔主动向用户打招呼 | 靠近用户 · 打招呼变体 |

### 5.2 形成规则（方向已确认，阈值候选）

- 不允许用户直接选择习惯；不能因一次行为形成稳定习惯。
- 需要多次真实自主选择，且跨多个有效活动日形成（候选阈值：至少 3 个不同 dayKey 且累计完成 5 次；待确认）。
- 同一日同一习惯最多计 1 次（候选），大量重复行为不能无限积累。
- 习惯影响后续自主行为概率（候选加成 ×1.5，待确认），但不彻底排除其他行为，最低出现概率仍生效。
- 习惯可以缓慢变化，不因离线自动衰减；已形成的习惯与标签不删除。长期行为分布变化可缓慢调整加成强度（候选机制，待确认）。
- 用户只能通过观察实际行为与资料页习惯标签发现习惯，不能看到隐藏分数或进度数值。
- 用户互动（点击、摸头等待确认交互目录）产生即时回应和共同回忆，但不能通过「摸头一次加一点亲近值」等方式直接刷性格或习惯进度。

## 6. 活动空间与世界成长

### 6.1 已确认需求

- 小白人拥有独立页面，活动场景足够宽敞；日记、角色和全部回忆不挤在同一个页面。
- 三页结构与静态宽场景已随 PR #5 合入 main（2026-11-08，本次修订执行期间合并）；自主行为尚未实现。
- 世界采用柔和、治愈的自然环境；小白人在场景中拥有真实的活动位置和可互动对象。
- 用户确认的不同情绪可以产生不同的短暂环境反馈；所有情绪都可以留下成长与回忆痕迹。

### 6.2 候选机制（待用户确认，不得当作已批准规则）

- 世界成长采用植物、简单家具和回忆纪念物表达。情绪种子候选机制：每条确认日记可留下一个由 label 决定外观的成长痕迹，关联 entryId / dayKey，由确定性规则生成；**不是需要反复刷取的货币**，无交易、消耗或价格体系。
- 花园、池塘、小屋等是否通过区域扩展解锁尚未确认；首版只保证大面积基础活动场景。地图结构、规模、资源消耗和解锁价格不擅自确定，列为后续待确认设计。
- 默认首页指向日记还是小白人世界待确认（见 §10）。

## 7. 日常互动与长期回忆

- 互动即时回应由本地确定性规则决定；可记录 COMPANION_INTERACTION 回忆（候选事件类型，C4 落地），关联时间与互动对象，不复制日记正文。
- 习惯形成记 HABIT_FORMED 回忆；世界成长痕迹记对应回忆（候选类型，C4）。纪念物由确定性规则按已确认事件生成，AI 不直接发放。
- 回忆沿用 P1 MemoryEvent 边界：Entry.text 是正文唯一正式存储位置，回忆经 entryId 关联，payload 不复制完整正文；情绪纠正历史与成长事件完整保留，普通负面情绪不删除任何历史。
- 角色资料页展示自然语言性格描述与习惯标签（§2.5），作为用户发现成长的入口。

## 8. 旧版机制衔接

旧 XP、成长阶段、装饰解锁与情绪触发隐藏/恢复规则归入「待废弃或待保留的旧版机制」，冲突分析与候选方案见 [PRODUCT_SPEC](PRODUCT_SPEC.md) 第 5 节；本文件不复制旧数值。隐藏性格、生活习惯和世界成长是新版主要玩法；新版不把悲伤等消极心情作为扣除成果的理由。原有成长数值与状态字段保留历史兼容，不擅自销毁数据。

## 9. 参数维护与验收

- 所有候选数值集中在本文件；实现时领域配置按本表落地并标记 `companion-v1`。
- C1 启动前，用户确认候选参数或明确授权按候选值开发（PR 标注「参数待验收」）；调参不追溯扣除已记录成长，只影响后续贡献。
- 调参后仅复测受影响的评分/截断/纠正关键案例，不开展大规模数值评测。
