## A. 已确定的产品决策

以下决策在后续开发中必须遵守；如需改变，应由用户重新确认并同步本文件与相关基线文档。

### A1. 角色身份

- 阶段七主角正式确定为**原创黑白企鹅**，不再以“全白小人”作为正式角色方向。
- 历史文档与已实现代码中的“小白人/白色小人”是阶段三的临时占位与历史事实，保留原描述，不追溯改写；新实现统一使用“原创企鹅”或“陪伴企鹅”。
- 企鹅是拾绪的长期陪伴角色，不是日记输入框旁的装饰，也不是只能被动响应的静态形象。

### A2. 视觉基准

- 以用户已确认的第一版圆润企鹅概念稿作为视觉基准。
- 经典黑白配色；允许橘黄色嘴巴和小脚。
- 身体圆润，短翅膀、小脚，保持可爱的幼态特征。
- 表情丰富、生动，具有较强的情绪表现力。
- **不添加腮红。**
- 风格为简洁、柔和、治愈的二维卡通。
- 具有明确身体结构和真实宠物般的生活习惯。
- 不直接复制第三方作品的角色造型。

> 概念稿目前只是已讨论确认的视觉方向，不代表仓库已有可直接使用的正式 SVG、表情、动画或其他美术资源。仓库实际只有白色小人占位，见 §D。

### A3. 表情系统原则

- 借鉴 React Kawaii 的**组件化结构**，但由拾绪自行实现：
  1. SVG 角色组件化设计；
  2. 身体与面部职责分离；
  3. 眼睛、嘴巴等部位独立控制；
  4. 根据当前状态组合表情；
  5. 不同表情下角色形象保持一致；
  6. 为后续动画过渡预留合理扩展空间。
- 表情状态来源保持现有边界：即时情绪只影响短时表情与动作幅度，主导性格决定长期行为倾向；不得用表情反向推断或修改性格。
- 不得把用户情绪机械映射为企鹅的同一种表情；表情选择应结合本次情绪与当前性格状态，具体映射仍属 §C 未定事项。

### A4. 动作与自主生活

- 企鹅应具备自主活动：待机、走路、转身、休息等基础行为，以及用户互动时的动作反馈和动作状态切换。
- 参考 Penguin-Pet 的自主活动、状态切换与按角色状态选择日常行为的思路，但**不引入完整桌面宠物框架**，不引入 Electron、后台常驻进程或新的运行时依赖。
- 行为选择继续由现有本地确定性行为引擎完成。企鹅表现层只消费 `BehaviorDecision` / `CharacterView`，不得重新抽取行为、改变权重、改变种子或绕过主导判定。
- 长期性格（温柔、好奇、开朗、害怕、低落）影响行为倾向；当前情绪只影响即时表现。不得改变五维评分规则、主导选择逻辑、持久化方式或自主生活领域契约。

### A5. 保存日记后的企鹅反馈（阶段七功能目标）

用户保存一条日记后，企鹅应产生短暂而自然的反馈，而不是只有机械的保存成功提示。目标流程：

1. 用户记录情绪并确认保存。
2. **只有正式保存成功后**，企鹅才触发反馈。
3. 企鹅暂时中断当前自主活动。
4. 企鹅转身或看向用户。
5. 根据本次情绪和现有性格状态，选择适当的短暂表情与动作。
6. 反馈结束后，企鹅恢复自主生活。

约束：

- 不重复触发导致行为异常；多次保存不得叠加出错误状态。
- 不破坏现有保存、历史记录、性格贡献、离线生活与久别重逢流程。
- 不把用户情绪机械映射为同一种表情。
- 不强迫用户进行互动；反馈是自然回应，不是任务或奖励。
- 现有阶段三已实现“保存成功后一次性反馈”的运行时触发与去重基础（`lastConfirmedSave`、`saveFeedbackDurationMs`、`reasonCode: "save_feedback"`）；阶段七升级的是企鹅的视觉序列与表现质量，不是重新定义保存结算。
- 具体动作、持续时间、中断优先级、异常处理与实现方式仍需详细设计，见 §C。

### A6. 生活空间与正式 UI 方向

- 设计方向：**简洁的大型生活空间 + 少量治愈系环境元素**。
- 借鉴温暖舒适的场景氛围、柔和自然光、少量植物/窗户/生活元素、清晰空间层次、角色在场景中的自然存在感，以及整体治愈系美术语言。
- 企鹅应拥有相对独立且足够大的生活空间，不应只是日记输入框旁边的小装饰。
- 不要求南极或冰雪主题。
- 正式 UI **尚未最终定稿**。首页结构、导航方式、日记输入区域位置、场景比例、响应式布局、动画方案等仍属 §C，不得自行写成最终规范。
- 阶段七解除 UI 冻结，但不等于可以删除已实现页面、导航或功能入口，也不等于可以引入 V1 明确不做的系统。

### A7. V1 范围边界

阶段七重点：

- 原创企鹅的正式视觉资源；
- 表情系统；
- 基础动作表现；
- 与已有自主生活系统的整合；
- 保存日记后的企鹅反馈；
- 独立生活空间；
- 正式 UI 体验。

V1 不开发：

- 服装与饰品系统；
- 家具收集；
- 物品商店；
- 金币或货币奖励体系；
- 不必要的复杂游戏系统。

未来装扮系统仍是 V2 的独立模块，按既有约定使用配置和资源驱动，不把装扮逻辑写死。V1 只保留 `AppearanceConfig` 等契约级扩展点。

### A8. 不变的领域与接口

阶段七不得改变：

- 五维性格名称、评分表、单次/单日上限、纠正替换与主导判定；
- 行为类别、主导行为池、权重规则、确定性抽样、防连续与隐藏暂停；
- 离线生活与久别重逢的领域契约、幂等和保存门控；
- AI 只产出情绪数据的权限边界；
- 存档 `schemaVersion` 3 与现有迁移规则；
- 保存失败不结算、不展示未落盘内容的正式状态边界。

如阶段七确需扩展 `CharacterView`、表情/动作目录或外观白名单，必须先更新 [ARCHITECTURE](ARCHITECTURE.md) 与调用方，再实现；不得用视觉任务顺带改变领域规则。

## B. 设计与技术参考

参考项目用于指导设计与实现思路，**不是技术依赖清单**，不意味着必须安装、引入或照搬。任何代码或素材复用都必须重新核实目标版本、许可与归属；许可不明时自行实现。

### B1. React Kawaii（表情系统结构参考）

- 仓库：<https://github.com/elizabetdev/react-kawaii>
- 许可：MIT（本次核实仓库元数据为 MIT）。
- 观察：角色拆分为独立组件，公共 `Face` 与路径定义被多个角色复用；表情通过有限属性组合，而不是为每个状态复制整套角色。
- 拾绪借鉴：身体/面部分离、眼睛/嘴巴等部位独立控制、状态组合、角色一致性、后续过渡扩展。
- 边界：不直接复制其角色造型；不因为借鉴结构就把它作为运行时依赖；若未来复制实质代码，保留 MIT 版权与许可文本。

### B2. Behance「LINEpenguin」企鹅表情作品（表情语言参考）

- 链接：<https://www.behance.net/gallery/155133579/LINEpenguin>
- 观察：简洁、生动的表情语言与身体表现方式，用少量形状传达明确情绪。
- 拾绪借鉴：表情的清晰度、身体姿态与情绪的一致性、可爱但不过度装饰的表达。
- 边界：仅作视觉学习；不得复制其具体角色形象、构图或受版权保护的美术素材。

### B3. Penguin-Pet（自主活动与状态切换参考）

- 仓库：<https://github.com/Myrrow/Penguin-Pet>
- 许可：仓库根目录含 MIT 许可文本（Copyright (c) 2026 ZFHR）；GitHub 元数据未自动识别许可，复用前仍需重新核实。
- 观察：Electron 桌面宠物；渲染层包含步态/运动与状态相关逻辑，资源以精灵图为主；具备自主活动与互动表现。
- 拾绪借鉴：待机、走路、转身、休息等基础行为，动作状态切换，按角色状态选择日常行为。
- 边界：不引入 Electron、桌面常驻、系统级窗口或完整宠物框架；不复制其美术素材；拾绪的行为选择仍由现有领域引擎决定，渲染层不重新决策。

### B4. Kinder World（生活空间与 UI 氛围参考）

- 链接：<https://www.playkinderworld.com/game>
- 观察：温暖舒适的场景氛围、柔和自然光、少量植物与生活元素、清晰空间层次、角色在场景中的自然存在感。
- 拾绪借鉴：生活空间的尺度感、治愈系美术语言、情绪记录带来的自然反馈。
- 边界：商业游戏，仅作视觉与交互参考；不得复制其场景、角色、UI 素材或代码；不要求采用其具体玩法、货币或收集系统。

## C. 尚未确定的设计事项

以下事项必须继续与用户讨论，**开发中不得自行定稿**。未确认前可以使用明确标识的临时实现或占位，但不得写成最终产品规范。

### C1. 正式 UI 与布局

- 首页结构：单页还是多页；记录、陪伴、回忆的入口与优先级。
- 导航方式：顶部、侧边、底部或场景内入口。
- 日记输入区域位置：独立页面、抽屉、浮层或场景内面板。
- 场景比例：生活空间与记录区域的视觉占比；企鹅的最小/最大显示尺寸。
- 响应式布局：窄屏、横屏、桌面端的重排规则。
- 动画方案：CSS、SVG、Web Animations 或其他方案；是否引入动画库。
- 空态、错误态、保存中、保存失败与离线恢复在正式 UI 中的表达。
- 可访问性细节：键盘操作、焦点顺序、对比度、屏幕阅读器描述。

### C2. 企鹅造型与资源

- 概念稿到正式 SVG 的比例、轮廓、翅膀/脚/嘴的具体形状与色值。
- `viewBox`、锚点、身体各部位坐标与图层顺序；现有白色小人使用 `0 0 240 320`，企鹅是否沿用尚未确定。
- 资源形式：内联 SVG、独立组件、精灵图或其他；是否支持多分辨率。
- 身体与面部的具体拆分粒度；眼睛、嘴巴、眉毛/眼睑、身体姿态的独立控制范围。
- 表情过渡：瞬时切换、短补间或后续动画；刷新与低动态模式下的回落。

### C3. 表情与情绪的映射

- 九类情绪（`joy` / `calm` / `sadness` / `anxiety` / `anger` / `tired` / `mixed` / `neutral` / `unknown`）各自的基础表情与幅度。
- 同一情绪在不同主导性格下的差异；如何避免“机械同一种表情”。
- 表情目录的命名、配置版本与可扩展方式。
- 互动、保存反馈、离线生活与久别重逢是否需要独立表情状态。
- 表情与 `amplitude`、`prefers-reduced-motion` 的组合规则。

### C4. 动作与状态机

- 基础动作清单与优先级：待机、走路、转身、休息、看向用户、互动回应等。
- 现有 27 个行为 ID（普通待机、五类主导行为、特殊行为与互动反应）如何映射到企鹅动作；是否新增动作 ID，新增时必须先更新契约。
- 动作持续时间、循环方式、结束回落与打断规则。
- 保存反馈的中断优先级：与互动、特殊行为、页面隐藏、连续保存的冲突处理。
- 企鹅是否在场景内自由移动，还是以固定站位配合位移/缩放表现。
- 页面隐藏、StrictMode、组件卸载、保存失败与重试时的计时器清理与状态恢复。

### C5. 保存反馈细节

- “转身或看向用户”的具体动作与时长。
- 反馈期间是否禁止或排队新的自主行为；连续保存时合并、排队还是丢弃。
- 保存成功后但组件已卸载、页面已隐藏或低动态模式下的降级。
- 反馈与离线事件、重逢问候同时出现时的顺序。
- 反馈是否需要文案；如需要，文案来源与是否配置化。

### C6. 生活空间细节

- 场景元素清单与数量上限；植物、窗户、光线、地面与背景层次。
- 白天/夜晚或时间带是否影响场景；如影响，必须使用应用层显式时间，不在渲染层调用隐式时间。
- 场景是否需要滚动、缩放或多区域；是否为未来场景扩展预留空间（V1 不实现家具，V2 仅规划饰品）。
- 场景资源体积、加载策略与降级方案。

### C7. 工程与验收

- 阶段七具体文件结构与配置命名；新增配置版本是否命名为 `character-v1` 仍需确认。
- 是否引入新的图片/动画处理依赖；引入前需评估体积、许可与必要性。
- 视觉验收标准：以人工对照概念稿为主，还是补充截图/像素检查。
- 阶段七与阶段八演示线的交接方式。
