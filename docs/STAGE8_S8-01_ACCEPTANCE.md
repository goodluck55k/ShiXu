## 4. 失败路径与恢复

| 场景 | 结果 |
| --- | --- |
| 存档损坏（非法 JSON） | 显示「本地存档已损坏」、原因、导出与重置；不自动覆盖；重置后恢复空存档 |
| 存档版本过新（`schemaVersion: 99`） | 显示「本地存档版本不支持」；重置后恢复 v4 空存档 |
| 跨标签页存档更新 | 合成 `storage` 事件后显示冲突提示，手选与保存按钮禁用；「重新加载存档」后恢复可写 |
| 跨标签页愿望更新 | 合成 `storage` 事件后显示愿望冲突提示，创建按钮禁用；「重新加载愿望」后恢复 |
| 愿望数据损坏 | 显示导出/重置/重新加载；面板显示不可用；创建区提示需先恢复；重置后恢复空集合 |
| 浏览器存储不可用（快照） | 显示存储不可用提示；进入临时体验后显示临时模式横幅，保存提示「仅本次会话」；刷新后临时记录消失，原正式存档未变 |
| 浏览器存储不可用（愿望） | 显示愿望存储不可用提示；创建按钮禁用并说明原因；不影响日记页 |
| 刷新恢复 | 日记正文/情绪/纠正、回忆记录与最新的第 1 页、愿望完成状态均在刷新后保留；回忆页不记忆上次阅读位置，与 ROADMAP 待验收项一致 |
| 未保存正文时离开回忆页（#45） | 站内导航弹确认：取消留页且草稿保留，确定才跳转；刷新/关闭浏览器走原生 `beforeunload` 提醒；后退/前进不弹确认但返回时恢复未保存草稿；放弃修改后草稿不写入存档，已保存正文/情绪/性格贡献/历史条数不变 |

## 5. 问题分级

### P0 / P1

- **P1-1（原登记 P2-1，[#45](https://github.com/goodluck55k/ShiXu/issues/45)，已修复）：回忆页未保存的正文编辑在应用内导航离开、刷新或浏览器后退/前进时静默丢失。** 审核复现与用户判断一致，定级由 P2 提升为 P1；位置 `src/components/memories/DiaryHistory.tsx`。
  - 第一轮修复：编辑脏状态下注册 `beforeunload` 守卫（刷新/关闭走浏览器原生离开提醒）；同时以捕获阶段的文档点击监听拦截站内链接，用 `window.confirm` 明确提示，确认后用现有 `useRouter().push` 跳转，取消则留在当前页并保留草稿。原有翻页草稿拦截 `navigateTo` 未改动；未引入路由框架或新依赖。
  - 第二轮修复（后退/前进）：真实 Chrome 复现确认 App Router 的后退/前进是同文档客户端导航，只触发 `popstate`、不触发 `beforeunload`，第一轮修复覆盖不到。Next.js 16.4.5 没有可取消客户端导航的路由守卫 API，Next 自身依赖 `popstate` 做路由恢复，因此不劫持 History API（会产生重复历史条目或导航竞态）。改为最小替代：同一标签页内把未保存草稿按条目暂存于内存，返回回忆页时自动恢复编辑并提示「已恢复上次未保存的修改，尚未保存。」；不写 `localStorage`、不改存档 Schema；链接确认离开时清除草稿，与确认文案一致。
  - 验证：见 §7.2、§7.3。两轮修复后未发现新的 P0/P1。
- 除 #45 外，四页主流程、无 Key 手选、存档损坏/版本过新、存储失败、跨标签页冲突与愿望持久化均可用；未发现其他阻塞演示主流程的缺陷。

**浏览器限制（已记录，不宣称可拦截）**：

- 刷新/关闭页面的提醒文案由浏览器控制，页面无法自定义（Chrome 显示通用文案，不显示 `returnValue` 文本）。
- 是否弹出提醒取决于浏览器策略与用户激活状态；移动端切后台、系统杀进程、崩溃不保证提醒。
- 站内拦截只覆盖普通 `<a href>` 左键点击；编程式 `router.push`、`target="_blank"`、外部站点、同页 hash 不在拦截范围。
- 浏览器后退/前进在 App Router 中属同文档客户端历史导航，只触发 `popstate`、不触发 `beforeunload`，无法在不劫持 History API 的前提下弹确认取消；第二轮改为返回时恢复草稿（§7.3），因此后退/前进不会出现离开确认，但内容不会静默丢失。
- 草稿恢复只覆盖同一标签页、同一会话；整页刷新或关闭标签页后内存草稿随之消失（刷新/关闭已有 `beforeunload` 提醒），浏览器崩溃、系统杀进程不保证任何提醒。
