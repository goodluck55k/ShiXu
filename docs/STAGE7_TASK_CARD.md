# 任务卡：阶段七 企鹅形象、表情动作、保存反馈与正式 UI（分支 feature/character-visual）

> 状态：**任务卡基线，尚未开工**。角色与功能目标已确认，正式 UI 布局、表情映射、动作参数与资源方案仍待确认；实施前先完成必要设计讨论。详细背景见 [STAGE7_DESIGN](STAGE7_DESIGN.md)。

### 归属与目标

- 阶段：阶段七 企鹅形象、表情动作、保存反馈与正式 UI
- 模块：`character`（角色展示、表情、动作、生活空间与正式页面表现）；只读消费 `personality`、`behavior`、`offlineLife`、`reunion` 的既有快照/视图。
- 一句话目标：用户记录并保存情绪后，一只原创企鹅在自己的生活空间里自然地看向用户、给出符合本次情绪与长期性格的短暂反馈，然后继续自主生活。
- 对应 Issue / PR：开工后填写。

### 输入与输出

- 输入：`CharacterView` / `BehaviorDecision`、只读主导性格快照与描述、当前确认情绪、`lastConfirmedSave` 一次性上下文、离线事件与重逢问候（既有展示门控）、应用层显式时间/种子/`dayKey`。
- 输出：企鹅 SVG 与组合表情、基础动作表现、生活空间与正式页面；保存成功后的短暂反馈序列；不产生新的正式存档状态。
- 状态所有权：仅运行时展示状态（当前表情、动作、反馈阶段、暂停/低动态）；不拥有性格、行为选择、日记、离线、重逢或存档状态。
- 不拥有：五维分数、主导判定、行为权重/种子、保存结算、离线窗口、重逢触发。

### 公共契约

- 新增契约：原则上无。若表情/动作目录或生活空间需要新的稳定 ID，先作为配置与视图扩展评审；不得直接新增存档字段。
- 修改契约：可能扩展 `CharacterView` 的受控字段（例如表情/动作 ID 的取值）或新增只读视图类型；任何修改必须先更新 [ARCHITECTURE](ARCHITECTURE.md) 与调用方。`CharacterView` 的只读语义不变。
- 消费的既有契约：`CharacterView`、`BehaviorDecision`、`BehaviorRuleConfig`、`PersonalitySnapshot`、`dominantDescription`、`EmotionReading`、`ConfirmedSaveContext`、`OfflineLifeEvent`、重逢问候对象。
- 禁止跨越：渲染层不得读取完整 `Snapshot`、不得调用评分/主导/行为选择函数、不得重新抽样、不得修改 `applyGameEvent` 的结算结果；不得导入服务端 AI 模块。

### 配置与版本

- 配置文件：阶段七新增角色/表情/场景配置（目标位置开工时确定）；现有 `src/config/behavior.ts` 的动作时长与行为映射只读复用，不在渲染层复制权重。
- 规则版本：不改变 `personality-v2`、`behavior-v2`、`offline-life-v1`、`reunion-v1`。如新增角色配置版本，候选命名 `character-v1`，待用户确认。
- 可调参数：表情切换时长、保存反馈时长、转身/看向用户时长、动作幅度、场景尺寸与响应式断点等均待设计；不得把候选值写成最终规范。

### 依赖与边界

- 前置依赖：阶段二～六已合入 `main`（PR #18、#19、#20、#22、#23）；现有行为运行时、保存成功门控、离线与重逢展示边界稳定。
- 明确不做：
  - 服装、饰品、库存、槽位、解锁、穿戴；家具收集、物品商店、金币/货币奖励。
  - V2 饰品业务与解锁逻辑。
  - 修改五维评分、主导判定、行为池/权重/种子/防连续、离线生活或久别重逢规则。
  - AI 决定动作、表情或行为；AI 生成美术。
  - Electron、桌面宠物框架、后台常驻进程；把 React Kawaii 或 Penguin-Pet 作为运行时依赖。
  - 复制第三方角色造型、场景、UI 或受版权保护的美术素材。
  - 未经确认的首页结构、导航、输入区位置、场景比例与动画方案定稿。
- 占位与真实：开工前可继续使用白色小人占位；阶段七必须交付原创企鹅正式视觉，不得把占位或概念稿描述为已完成资源。概念稿不是仓库内可直接使用的 SVG。

### 最小验收

- [ ] 企鹅形象原创，符合已确认的圆润黑白造型、橘黄嘴/脚、无腮红与治愈系二维风格；不复制第三方角色。
- [ ] 身体与面部职责分离，眼睛、嘴巴等部位可独立组合；九类情绪表情可辨认，不同表情下角色形象一致。
- [ ] 五类主导性格的行为仍可辨认；待机、走路、转身、休息与互动反馈可在生活空间中表现。
- [ ] 页面隐藏暂停行为与动画；`prefers-reduced-motion` 降级仍生效；刷新后视图与正式状态一致。
- [ ] 保存成功后只触发一次自然反馈：中断当前活动、转身或看向用户、按情绪与性格选择短暂表现、结束后恢复自主生活；保存失败不触发。
- [ ] 连续保存、互动打断、页面隐藏、组件卸载与重试不会造成重复反馈、计时器泄漏或状态错乱。
- [ ] 不出现服装、饰品、家具、商店或金币入口；不改存档 `schemaVersion` 与既有领域规则。
- [ ] 正式 UI 在用户确认布局后完成；空态、错误态、保存中/失败、离线恢复与窄屏可用。
- 验证方式：人工页面冒烟 + 必要的规则/运行时回归 + 一次 typecheck/lint/build；不要求覆盖率。
- 未验证项：真实美术资源完成度、不同设备/浏览器的动画表现、用户最终视觉验收。

### 存档与迁移

- schema 变化：无（保持 `schemaVersion` 3）。
- 迁移策略：不涉及；不得为视觉任务新增持久字段或复用 `legacy` 执行业务。
- 失败处理：保存失败不触发反馈、不改变正式状态；展示层错误不得导致存档写入或结算。

### 风险与待确认

- 正式 UI 布局、导航、输入区位置、场景比例、响应式与动画方案未定，开工前需用户确认。
- 表情与九类情绪/五维主导的映射、保存反馈动作与时长、中断优先级、连续保存策略未定。
- 企鹅 `viewBox`、部位拆分粒度、资源形式与性能预算未定。
- 现有白色小人占位与临时场景不得在未确认时直接改造成“最终视觉”；阶段七解除 UI 冻结不等于可任意重设计。
